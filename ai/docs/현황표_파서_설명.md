# 설비 현황표 파서 — 무엇을 하고, 어떻게 돌아가고, 결과는 무엇인가

> B106 데이터/AI 파트 · 2026-10-29 · 대상: 멘토님, 팀원

---

## 1. 한 줄 요약

**사람이 보는 엑셀 현황표를 "설비 한 대 = 한 줄"인 표로 바꿔주는 프로그램**입니다. 글자는 바꾸지 않고, 이상한 곳에는 꼬리표(이슈)만 붙입니다. 이 표가 가져오기 검토 화면에 뜨고, 사용자가 확인한 뒤 DB에 저장됩니다.

```
[현황표 엑셀]  →  [파서]  →  [설비 행 목록 + 이슈 + 원본 위치]  →  [검토 화면]  →  [DB 저장]
```

---

## 2. 입력과 출력을 그림으로

**입력** (평택 P1 시트 일부 — 표가 좌우로 두 개, 블록 제목이 왼쪽에)

```
P1F(3F)   Poly                               Oxide
(61)      No  설비군  설비호기  Version       No  설비군  설비호기  Version
          1   M-C3    ESPA02   v3.52_22      1   M-O2    ESOS21   v3.53_2
          2   M-C3    ESPR45   v3.52_13      2   M-O2    ESOG72   v3.53_2
```

**출력** (설비 한 대가 한 줄)

| site | sheet | line | floor | process_group | group_raw | equipment_code | version_raw | issues | src |
|---|---|---|---|---|---|---|---|---|---|
| 평택 | P1 | P1F | 3F | Poly | M-C3 | ESPA02 | v3.52_22 | DUPLICATE_EQUIPMENT | P1!R3C7 |
| 평택 | P1 | P1F | 3F | Oxide | M-O2 | ESOS21 | v3.53_2 | | P1!R3C18 |

엑셀 한 줄(3행)에서 설비 두 대가 나온 것, 왼쪽 블록 제목이 line/floor로 풀린 것, 첫 줄에 "중복" 꼬리표가 붙은 것을 보면 됩니다.

## 3. 저장되는 CSV — 열마다 뜻

`demo.py`가 만드는 `parsed/*.csv`입니다. (JSON도 같은 내용이며 백엔드용)

| 열 | 뜻 | 예 |
|---|---|---|
| `site` | 사업장. 시트 이름을 보고 자동 추정 (Memory/Foundry → 화성, P1·S5 → 평택) | 평택 |
| `sheet` | 읽은 시트 | P1 |
| `line` | 라인. 평택은 왼쪽 블록 제목 `P1F(3F)`에서, 화성은 Line 열에서 | P1F / 13L |
| `floor` | 층. 블록 제목의 `(3F)` | 3F |
| `process_group` | 표 제목(Poly/Oxide/HPA). 화성은 '설비군' 열(Poly/Oxide) | Poly |
| `production_area` | 메모리/파운드리 **기본값**. 화성은 시트명, 평택은 S5·V2·P3-S5만 FOUNDRY | MEMORY |
| `group_raw` | 설비군 칸의 **글자 그대로**. 번역표(model_alias)로 설비군을 찾는 열쇠 | M-C3 (6각) (통합UI) |
| `equipment_code` | 설비호기. `ESJOF06 (JEP)`면 `ESJOF06` | ESPA02 |
| `equipment_tail` | 설비호기 뒤 꼬리말 | (JEP) |
| `version_raw` | 버전 칸의 글자 (앞뒤 공백만 제거, 대소문자·구분자는 그대로) | `V3.53_2` |
| `versions` | 버전을 분리한 것. 보통 1개, PM 혼합 설비는 `O3:v4.50.1.1_a \| O2:v3.53_F2` 2개 | v3.53_1 |
| `issues` | 꼬리표. 아래 4장 | VERSION_WHITESPACE |
| `src` | 원본 셀 주소 (시트!R행C열, 버전 칸 기준). 검토 화면 "원본 보기"용 | P1!R5C7 |
| `extras` | 나머지 칸 전부(JSON). No, PM, Bay, 비고, 제목 없는 메모 등. 버리는 칸이 없음 | {"no":"3"} |

샘플 다섯 번째 줄을 읽어보면: 평택 P1 시트 P1F 3층 Poly 표의 `M-C3` 설비 `ESPQ69`는 버전이 `v3.53_1`이고(원본 셀엔 끝에 공백이 있었지만 조용히 제거), 원본은 P1 시트 5행 7열(G5)이다 — 이렇게 됩니다.

## 4. 꼬리표(issues) 목록 — 검토 화면이 보고 처리할 것

| 꼬리표 | 언제 붙나 | 검토 화면·집계에서 |
|---|---|---|
| `VERSION_MISSING` | 버전 칸이 빈 칸 | "누락". 전체 대수에는 넣고, 업그레이드 필요에는 안 넣음 (10/28 멘토 이의 없음) |
| `VERSION_TEXT` | 버전 칸에 글자만 (`메모리버전임`) | 누락 처리 + "이 설비는 메모리 릴리즈노트?" 힌트(`extras.area_override_hint`) |
| `MULTI_VERSION` | 한 칸에 두 버전 (`O3: … / O2: …`) | PM 혼합 설비 → O2·O3 양쪽에 1대씩 (10/21) |
| `EQUIPMENT_TAIL` | 설비호기에 `(JEP)` 같은 꼬리말 | 꼬리말은 비고로 |
| `EQUIPMENT_MISSING` | 설비호기는 없는데 버전이 있음 | 사용자 확인 |
| `DUPLICATE_EQUIPMENT` | 파일 안에서 같은 설비호기가 두 번 | 저장 전 하나 선택. 설비호기는 전 사업장 유일(10/27)이므로 무조건 오류 |
| `ANALYSIS_EXCLUDED` | HPA | 저장은 하되 집계·그래프 제외 (10/14) |

시트 단위 메시지:
- **경고** `블록 'P1F(3F) (61)': 선언 대수 61 ≠ 읽어낸 설비 23` — 블록 제목의 대수와 실제 읽은 설비 수가 다름. **경고만 띄우고 저장은 막지 않음**(팀 검토 의견). 연습 데이터는 일부러 다르게 둠.
- **슬롯** `설비호기 미입력 슬롯 77개` — 설비군만 적혀 있고 설비호기가 빈 줄. 멘토님 원본(빈 양식)이 이 경우. 저장 대상 아님.
- **AI 열 매핑 필요** — 제목줄 자체를 못 찾은 시트(예: "P1과 유사"라고만 적힌 자리표시 시트). 에러가 아니라 다음 단계(AI한테 열 위치 묻기)로 넘기는 신호.

## 5. 어떻게 돌아가나 — 사람이 하는 행동을 그대로 옮김

| 단계 | 사람이 하는 일 | 코드가 하는 일 |
|---|---|---|
| 1 | 엑셀을 연다 | 시트를 "행마다 칸 값 목록"인 2차원 표로 받는다 (파일이든 열린 엑셀 창이든 같음) |
| 2 | "설비호기, Version이 적힌 줄이 제목줄이네" | **별칭 사전**(설비호기=설비명=호기=equipment…, Version=Ver=버전=SW VER…)으로 제목줄 찾기. 열 번호가 아니라 이름으로 찾으므로 열이 한 칸 밀려도(화성 Foundry) 상관없음 |
| 3 | 화성은 제목이 두 줄이네 (Version 아래 SW/Engine) | 아랫줄이 SW·Engine·Flow·Bay 같은 세부 단어만 있으면 두 줄 제목으로 보고 `Version/SW`처럼 합침 |
| 4 | 평택은 표가 옆으로 두 개네 | 제목줄에 `No`가 두 번 나오면 그 위치에서 끊어 표(세그먼트) 2~3개로 분할. 한 행에서 설비 2~3대 |
| 5 | 버전 열이 어느 거지? Engine 말고 SW | 후보 열에 점수: `SW` +20, `Engine`·`EPD`·`IP` −50 → 최고점이 버전 열 |
| 6 | 왼쪽에 `P1F(3F) (61)` 블록 제목 | 라인 P1F, 층 3F, 선언 대수 61로 분해. 블록마다 반복되는 제목줄 = 블록 하나 |
| 7 | 병합된 Line 칸은 위 값이 이어지는 거지 | 빈 칸이면 바로 위 값을 끌어내림(fill-down). 완전 빈 줄, 떠돌이 글자, 설비호기 없는 슬롯은 건너뜀 |
| 8 | `ESJOF06 (JEP)`은 설비호기 + 메모 | 꼬리말 분리. 버전 칸은 빈칸/글자만/두 버전/정상 네 가지로 판정. **글자는 안 바꿈** |
| 9 | 이상한 데 표시 | 행마다 꼬리표, 블록마다 대수 경고 |
| 10 | 파일 전체에서 같은 호기 있나 | 모든 시트를 읽은 뒤 설비호기 중복 검사 |

**설계 원칙 세 가지**
1. **이름으로 찾고 번호로 안 찾는다** — 사업장마다 열 위치가 달라도 코드 수정 없음.
2. **글자를 안 바꾸고 꼬리표만 단다** — 원본 셀 주소를 같이 저장하므로 "왜 이렇게 읽혔지?"를 바로 확인. 멘토님 요구 "사용자 검토·수정 후 저장"의 전제.
3. **입력은 파일이 아니라 표** — 개발은 파일로, 회사에서는 열어둔 엑셀 창(xlwings)으로, 코드는 하나.

AI는 여기서 **안 씁니다.** 규칙으로 읽히는 양식(지금까지 받은 전부)은 규칙으로 읽고, 못 읽는 새 양식이 왔을 때만 AI에게 "제목줄 위치와 열 역할"을 묻는 구조입니다.

## 8. 다음 단계와의 연결

- **릴리즈노트 파서(B)** — 같은 방식으로 릴리즈노트를 "버전 사다리"로.
- **번역표·버전 맞추기(C·D)** — 이 파서의 `group_raw`를 번역표로, `versions`를 사다리와 4단계 매칭(그대로 → 구분자 떼고 → 후보 선택 → 미등록). 글자를 바꾸는 건 거기서.
- **AI 열 매핑(E1)** — `needs_ai_mapping`인 시트만.
- **백엔드** — JSON 그대로 `equipment_snapshot`(설비·라인·사이트) + `equipment_version`(버전 원문·이슈) + `import_batch`(원본 위치)에 들어가는 모양.
