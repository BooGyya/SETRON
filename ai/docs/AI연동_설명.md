# AI 연동(E1·E2·E3) — 무엇을 하고, 어떻게 돌아가고, 어떻게 쓰나

> B106 데이터/AI 파트 · 2026-11-02 · 골든테스트 80개 통과(오프라인) · 실제 GMS 호출 정답률은 `eval_query.py` 로 측정

---

## 1. 전체 그림 — AI 는 세 군데에서만 일한다

이 프로그램에서 AI 가 하는 일은 셋뿐입니다. 숫자 계산은 전부 코드가 하고, AI 는 **말을 알아듣고(E2), 낯선 표의 구조를 알아보고(E1), 숫자를 글로 풀어주는(E3)** 역할만 맡습니다. 이 원칙은 1차 멘토링 때 "AI 가 실수할 수 있으니 결과는 사용자가 검토 후 저장"이라고 한 요구를 지키기 위한 것입니다. 세 기능은 모두 `svhm/ai/llm_client.py` 하나를 통해 서버를 부르고, 그 파일 밖의 코드는 어느 서버·어느 모델인지 모릅니다.

---

## 2. 공통 — `llm_client.py` 는 왜 이렇게 생겼나

개발은 SSAFY GMS(`https://gms.ssafy.io/gmsapi/api.openai.com/v1`, gpt-5)로 하고, 인계할 때는 세메스 사내 서버(vLLM, OpenAI 호환, gpt-oss-120b 추정)로 바꿔야 합니다. 둘 다 OpenAI 호환이라 같은 SDK 를 쓰지만 세부가 다릅니다. gpt-5 는 `temperature` 를 받지 않고 `max_completion_tokens` 를 쓰는 반면, vLLM 은 예전 방식(`temperature`, `max_tokens`)입니다. 사내 서버가 `response_format: json_object` 를 지원하는지도 아직 모릅니다. 그래서 설정을 환경변수로 뺐습니다.

```
SVHM_LLM_BASE_URL / SVHM_LLM_API_KEY / SVHM_LLM_MODEL       ← 인계 때 바꾸는 세 줄
SVHM_LLM_PARAM_STYLE = openai5 | classic                    ← gpt-5 / vLLM
SVHM_LLM_JSON_MODE   = auto | on | off                      ← auto: JSON 모드가 거부되면 자동으로 끄고 재시도
SVHM_LLM_MOCK        = 1                                    ← 서버 없이 흉내 (테스트·오프라인)
```

`complete_json(system, user, schema)` 하나가 핵심입니다. 응답에서 코드펜스나 앞뒤 설명이 섞여 있어도 JSON 만 뽑아내고, pydantic 스키마로 검증하고, 틀리면 "이전 응답이 형식에 안 맞았다"를 붙여 한 번 더 묻습니다. 모든 호출은 `logs/llm_calls.jsonl` 에 모델·소요 시간·토큰 수·프롬프트 해시(본문은 아님)로 남아서 나중에 크레딧·속도를 볼 수 있습니다. 실데이터는 GMS 로 보내지 않습니다. 연습 데이터만 보내고, 실데이터는 사내 서버에서만 돕니다.

## 3. E2 — 자연어 질문 → 조회 조건 JSON

"평택 O2 중 두 칸 이상 뒤처진 설비만 보여줘"를 받으면 AI 가 아래 JSON 을 만듭니다.

```json
{"intent": "query", "sites": ["평택"], "groups": ["O2"],
 "relative": {"op": "steps_below_at_least", "steps": 2}, "chart": "treemap"}
```

이 JSON 이 곧 **조회 조건 객체**입니다. 대시보드 체크박스를 눌러도 같은 모양이 만들어지고, 아이템 매니저·AI 분석 탭에서 말로 물어도 같은 모양이 만들어져서 백엔드 집계 API 로 갑니다(2차 멘토링에서 확정한 "조회 조건 공유"). 필드는 intent(query/item/why/forecast/report/priority), 사이트·라인·메모리/파운드리·대분류·설비군, 기준일, 기준 버전(최신/지정), 상대 조건(미만/이상/n칸 이상 뒤처짐), 위험만, 아이템 검색어, 그래프 종류, 되묻기 여부입니다.

프롬프트에는 어휘를 박아 넣습니다. 설비군 13개 이름, 사이트, 라인, 메모리/파운드리 규칙, 그리고 함정 하나 — **'O2' 는 Oxide 의 M-O2 이고 'Inline O2'·'Cluster O2' 는 이름에 O2 가 있어도 KCTC** 라는 것. 어휘에 없는 말('C5', '구미', '아까 그 라인')이 오면 억지로 추정하지 말고 `need_clarification=true` 로 되묻게 했습니다. AI 가 돌려준 JSON 은 코드가 한 번 더 걸러서, 모르는 설비군·사이트는 지워지고 그 경우 되묻기로 바뀝니다.

정답률은 **예문 30개**(`query_examples.json`)로 잽니다. 각 예문에 "이 필드는 이 값이어야 한다"가 적혀 있고 `eval_query.py` 가 문장 정답률·필드 정답률을 냅니다. 오프라인 mock 으로는 30/30 이지만 그건 채점기가 돌아가는지 확인한 것이고, **GMS gpt-5 로 돌린 수치**가 진짜 성적입니다. 사내 서버에서도 같은 30문항을 돌리면 모델이 바뀌어서 떨어진 게 있는지 바로 보입니다.

## 4. E1 — AI 열 매핑

현황표·릴리즈노트 파서는 제목줄을 이름으로 찾기 때문에 지금까지 받은 양식은 전부 규칙으로 읽힙니다. 규칙이 실패하는 경우는 둘입니다. 제목이 전혀 다른 말로 적힌 새 사업장 양식, 그리고 버전이 가로로 늘어선 릴리즈노트(우리 O2 가로형 테스트 파일). 이때만 시트 상단 20행을 '행번호 | 셀 | 셀 …' 텍스트로 만들어 AI 에게 **구조만** 묻습니다. 문서 종류(현황표/릴리즈노트), 세로/가로, 제목줄 번호, 어느 열이 설비호기·버전·설비군인지, 나란한 표 수, 블록 제목 열. 값의 뜻은 묻지 않습니다.

받은 답(ImportProfile)은 두 가지로 씁니다. 현황표면 AI 가 알려준 열에 표준 이름(설비호기/Version/설비군)을 끼워 넣고 **규칙 파서를 다시 부릅니다.** 가로형 릴리즈노트면 표를 전치(행↔열)해서 **릴리즈노트 파서를 다시 부릅니다.** 즉 AI 는 "어디가 뭔지"만 알려주고 읽기는 늘 같은 규칙 파서가 합니다. 그래서 AI 가 틀리면 파서 결과가 이상해지고(설비 0대 등) 사용자가 검토 화면에서 바로 알아챌 수 있습니다. 한 번 알아낸 프로파일은 `import_profile` 테이블에 저장해서 같은 시트는 다음 달부터 AI 없이 읽습니다.

## 5. E3 — 보고서 문장 생성 · 파편화 원인 분석

보고서는 코드가 먼저 숫자를 다 만듭니다. 적용률·업그레이드 필요·미등록·누락, 위험 설비 수와 규칙, 우선순위 상위 5, 예측 문장, 날짜별 스냅샷. 이 JSON 을 AI 에게 주고 "이 숫자를 새로 계산하거나 추정하지 말고 설명만 하라"고 시킵니다. 돌아온 글에서 숫자를 전부 뽑아 **입력에 없는 숫자가 있으면 경고**를 붙입니다(숫자 지어내기 방지). 예측 문장에는 "참고용"과 데이터 장 수가 반드시 들어가게 했습니다.

파편화 원인 분석(`why`)은 같은 구조에 데이터만 다릅니다. 범위 안의 버전별 설비 수, 각 버전의 출시일, 그 버전으로 올리려면 하드웨어 변경이 필요한지(릴리즈노트 C4 의 `HW연관` 열), 고객사 연관, 핫픽스 여부, 환경안전 항목 수를 주면 AI 가 "43버전은 HW 변경이 선행돼야 해서 패치가 늦어졌다"처럼 2차 멘토링에서 멘토님이 든 예와 같은 설명을 데이터 근거로 씁니다. 데이터에 없는 이유는 "확인 필요"로만 쓰게 했습니다.

결과는 제목·요약·절(현황/위험/우선순위/전망)·주의 로 된 JSON 이고 마크다운으로 바꿔 보여줍니다. Word 로 내보내는 건 백엔드/프론트에서 python-docx 로 이 구조를 그대로 찍으면 됩니다.

## 6. 실행 (GMS)

```
copy .env.example .env         ← SVHM_LLM_API_KEY 에 GMS 키 입력
python demo_ai.py ping                                          # 연결 확인
python demo_ai.py query "평택 O2 중 두 칸 이상 뒤처진 설비만 보여줘"
python eval_query.py                                            # 30문항 정답률 (gpt-5 크레딧 소모: 문항당 1회)
python demo_ai.py map P_PJT_M-O2_SW_정기_Release_List_교육용_가로형_AI테스트용.xlsx Memory
python demo_ai.py report --status . --release . --mentor . --site 평택 --family "O2 (메모리)"
python demo_ai.py why    --status . --release . --mentor . --site 평택 --family "C4 (메모리)" --line P1D
python -m pytest tests -q                                       # 80 passed (AI 는 mock)
```
크레딧이 아까우면 `.env` 의 `SVHM_LLM_MODEL=gpt-5-mini` 로 바꿔 돌려보고, 정답률이 비슷하면 그걸로 개발하면 됩니다.

## 7. 인계 준비물

사내 서버로 바꿀 때 멘토님이 돌릴 수 있는 것: `.env` 세 줄 교체 → `python demo_ai.py ping` → `python eval_query.py`. 통과 수가 GMS 와 같으면 끝이고, 떨어지면 떨어진 문항의 프롬프트를 손봅니다. 실데이터는 한 줄도 밖으로 나가지 않습니다.
