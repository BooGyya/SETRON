# 위험 판정 · 노후도 색 · 우선순위 · 통일 예측 — 무엇을 하고, 어떻게 돌아가나

> B106 데이터/AI 파트 · 2026-11-02 · 대상: 멘토님, 팀원 · 골든테스트 E6~E10 통과 (전체 72개)

---

## 1. 무엇을 만들었나

버전 맞추기까지 끝나면 설비마다 "어느 릴리즈노트 몇 번째 칸"이 정해집니다. 그 위에서 멘토님이 3차 멘토링(10/21)에서 정해 준 네 가지를 계산하는 코드입니다. 어느 설비가 **위험**한지, 각 설비의 버전이 얼마나 **오래됐는지**(색), 어느 설비부터 **올려야** 하는지(우선순위), 지금 속도면 **언제 다 끝나는지**(예측)입니다. 숫자 계산은 전부 코드가 하고 AI는 관여하지 않습니다. AI는 나중에 이 숫자를 받아 문장으로 설명하는 역할만 맡습니다.

---

## 2. 위험 판정은 어떻게 하나

멘토님은 위험 설비를 두 가지로 정의했습니다. 하나는 **환경안전 필수 아이템이 아직 안 깔린 설비**이고, 다른 하나는 **결함이 있어 핫픽스가 필요한 버전을 쓰는 설비**입니다. 둘 중 하나만 해당해도 위험입니다. 그런데 어떤 아이템이 환경안전 필수인지, 어떤 버전에 결함이 있는지는 릴리즈노트에 적혀 있지 않은 경우가 많아서, **사용자가 직접 등록**하게 하라고 했습니다.

그래서 코드는 "위험 규칙"이라는 작은 데이터를 받습니다. 규칙 하나는 "어느 릴리즈노트(계열)의, 어느 버전부터, (결함이면) 어느 버전 전까지, 왜"를 담고 있고, 백엔드 ERD의 `risk_rule` 테이블과 같은 모양입니다. 환경안전 규칙은 "이 아이템이 v4.56.6.43에 들어갔다"고 적으면 되고, 그러면 같은 줄기에서 v4.56.6.43보다 아래 칸에 있는 설비가 전부 위험이 됩니다. 몇 칸 아래인지도 같이 알려줍니다("현재 v4.56.6.41_d5, 3칸 아래"). 결함 규칙은 "v3.52_13_a2부터 v3.52_13_e 전까지"처럼 구간으로 적으면 그 구간 안의 버전을 쓰는 설비가 위험이고, 해제 버전을 비워두면 그 뒤로 전부 위험입니다. 규칙은 같은 릴리즈노트의 같은 줄기(기본/DFB/DEX)에만 적용되므로 C4 규칙이 O2 설비에 영향을 주는 일은 없습니다.

사용자가 등록할 때 도움을 주려고, 릴리즈노트 파서가 "환경안전"이나 "Interlock"이 들어간 항목과 P0 항목에 **후보** 표시를 해 둡니다. 자동으로 위험으로 지정하는 것이 아니라 등록 화면에서 "이런 항목이 있는데 등록할까요?"라고 추천하는 용도입니다.

## 3. 노후도 색은 어떻게 정하나

멘토님은 지금까지 수작업으로 버전 출시 후 1년 미만이면 초록, 1년 이상이면 주황, 2년 이상이면 빨강으로 칠해 왔다고 했고, 이 숫자는 임의 기준이니 설정에서 바꿀 수 있게 하라고 했습니다. 코드는 설비가 연결된 칸의 출시일과 기준일(현황표 날짜)의 차이를 일수로 구해 색을 정하고, 1년·2년 기준은 바꿀 수 있는 값으로 두었습니다. 연습 데이터는 전부 2026년 출시라 지금은 모두 초록인데, 기준일을 2027년 12월로 바꿔 돌리면 주황·빨강으로 갈립니다. 출시일이 없는 칸이나 연결되지 않은 설비는 회색입니다.

주의할 점은 이 색이 **"기준 버전 N과의 거리"가 아니라 "버전의 나이"**라는 것입니다. 우리가 처음에 생각했던 "N에서 몇 칸 아래"는 업그레이드 필요 수를 셀 때 쓰고, 색은 멘토님 방식대로 나이로 칠합니다.

---

## 4. 우선순위는 어떻게 매기나

멘토님 기준 그대로입니다. 위험 설비가 먼저, 그다음 버전이 가장 낮은 설비, 그다음 낮은 순입니다. 같은 칸이면 출시일이 오래된 쪽이 먼저입니다. 연습 데이터 평택을 돌리면 1~4위가 환경안전 규칙에 걸린 O2·C4 설비이고 5위부터는 "버전 낮음"으로 이어집니다. 사유가 문장으로 붙어 있어서 목록을 그대로 화면에 띄우면 됩니다.

---

## 5. 통일 예측은 어떻게 하나

멘토님은 예측이 보조 기능이라 정확도에 민감하지 않고, 데이터가 적을 때는 "2대 올리는 데 10일 걸렸으면 40대는 그에 비례"처럼 단순 비례로 해도 된다고 했습니다. 코드는 날짜별 현황표에서 같은 범위·같은 N으로 센 적용 대수를 점으로 찍고, 처음 점과 마지막 점 사이의 평균 속도(대/일)로 남은 대수를 나눕니다. 결과는 "남은 29대, 최근 속도 0.14대/일 → 약 203일 뒤 2027-04-26 완료 예상 (참고용, 데이터 3장)"처럼 나옵니다. 스냅샷이 1장뿐이면 "예측 불가 — 날짜가 다른 현황표가 2장 이상 필요", 기간 동안 적용 대수가 늘지 않았으면 "예측 불가", 이미 다 깔렸으면 "완료"입니다. 데이터가 쌓이면 이 자리에 더 나은 계산을 넣으면 되고, 화면에는 항상 "참고용(데이터 n장)"이 따라붙습니다.

연습 데이터는 8/3, 9/1, 10/5 세 장을 만들어 두었기 때문에(멘토님: 과거 현황표는 복사해서 버전 낮추고 날짜 바꿔 쓰라) 평택 10개 계열에 대해 예측이 돌아가고, KCTC 두 계열처럼 증가가 없는 곳은 예측 불가로 표시됩니다.

## 6. 실행과 결과

```
python demo_risk.py --status <현황표 폴더> --release <릴리즈노트 폴더> --mentor <멘토 원본 폴더> --site 평택 --out parsed_risk
python demo_risk.py ... --site 화성 --asof 2027-12-01     # 기준일을 바꿔 노후도 색 확인
python -m pytest tests -q                                 # 72 passed
```
현황표 폴더에서 `평택…_2026-08-03.xlsx`처럼 날짜가 붙은 파일을 전부 읽어 예측에 씁니다. 화면에는 위험 설비 수와 규칙별 대수, 노후도 색 분포, 우선순위 상위 10, 계열별 예측이 뜨고, `*_위험판정_날짜.csv`에 설비마다 순위·위험 여부·사유·색·출시 후 일수가 저장됩니다. 데모의 위험 규칙 세 개는 코드에 적어둔 예시이고, 실제로는 사용자가 등록 화면에서 입력한 것이 `risk_rule`에서 읽혀 옵니다.
