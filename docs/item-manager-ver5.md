## 데이터 경계

- Figma 예제의 설비명·버전·대수·문서/원본 셀을 운영 데이터로 복사하지 않는다.
- 2026-11-07 사용자 확인: 동일 계열에서 최초 포함된 Item은 확인된 후속 버전에도 누적 적용된다. 최초 포함 이전은 미적용이다.
- 명시적으로 저장된 상태는 우선하며 순서 미확인·중복·계열/모델 범위 미확인은 추정하지 않는다. 원본 행을 복제하거나 DB를 자동 변경하지 않는다.
- AI는 관련 Item을 찾는 데 사용하고, 버전 포함 상태·설비 대수·적용률·위험은 검증된 로컬 서비스로 계산한다.
- 질문/화면 이동/미리보기만으로 DB를 변경하지 않는다. 위험 등록은 명시적 저장 동작과 기존 트랜잭션·재판정 경로를 사용한다.
- 실제 회사 AI 호출 및 운영 DB 저장은 별도 사용자 실행으로 확인한다. 자동 검증은 모의 응답과 격리된 테스트 DB를 사용한다.

## 앱에서 확인하는 위치

- 좌측 `아이템 매니저` → 상단 고정 `Item 분석` / `Item 관리` 탭.
- `Item 분석` → 계열 칩 아래 질문 입력·AI 검색 → 원본 표 위 파란 답변 카드. 선택한 Item의 원본 근거 행은 노란색으로 표시한다.
- 원본 표의 문서·시트 선택에서 실제 원본 열을 변경한다. 보관된 원본이 없으면 현재 관리값 표임을 명시한다. JIRA·비고 등의 값을 만들어 넣지 않는다.
- 답변 아래 이동 버튼: AI 분석은 팀원 작업의 대화 화면에 초안만 전달한다. 히트맵/대시보드는 선택 계열·관측일·포함 기준 N을 명시적으로 적용한다. 검색 자체는 전역 조건을 변경하지 않는다.
- `Item 관리` → 상단 5개 필터 / 가운데 등록 기준 카드 / 아래 설비별 PM 상태 표 / 오른쪽 `+ 위험 아이템 추가`.
- 추가 창은 이름·구분·원본 Item·판정 방식·복수 설비군·Site/Line·메모를 받는다. `영향 미리보기`와 원본 확인 체크 후에만 `추가`할 수 있다. 취소·입력 변경·중복 클릭은 저장하지 않는다.

## Jira 코드·위험 후보 연결 (feature/item-jira-risk-link)

- 목록 행은 `포함 릴리즈 · Item 제목 · Jira`를 한 줄에 보인다. 펼친 상세 첫 줄에도 `포함 릴리즈 · Item No · Jira`를 둔다.
- Jira는 가져오기 때 보관한 원본(`import_batch.raw_data`)에서 Item 출처(`source_reference`)가 가리키는 행의 값만 쓴다(`ui/item_original.py`의 `item_jira`). 머리글에 `JIRA`가 들어간 열, `Issue`/`Ticket`/`항목 ID` 열은 셀 원문을 쉼표·줄바꿈으로 나눠 쓰고, `REMARK`/`비고` 열은 실제 적힌 `ABC-123` 모양만 쓴다. 코드를 만들거나 고치지 않는다.
  - **11-13: 읽을 열은 릴리즈노트 가져오기와 같은 규칙으로 시트마다 하나 정한다**(`features/item/original._sheet_jira` → `rule_extraction.release_rules.find_header · _jira_column`). 11-12 멘토 답변대로 설비군마다 머리글이 달라서(O2 `Issue` · O5 `JIRA` · O3 `JIRA ID` · C4 `REMARK`) 머리글 줄과 바로 아래 보조 머리글 줄에서 Jira 열을 먼저, 없으면 비고 열을 쓰고, 둘 다 있으면 Jira 열만 쓴다(비고의 코드는 합치지 않음). 이름으로 못 찾으면 Item 행 절반 이상에 `ETOJ-1234` 모양이 있는 열을 쓴다. 내용 머리글이 `Description`인 C3 노트도 읽는다. 세로형 머리글이 없는 시트(버전이 열로 놓인 교육용 O2 등)는 예전처럼 행 머리글로 읽는다.
- 코드가 없으면 `Jira 없음`(Jira 칸이 비었거나 `-`)과 `Jira 미확인`(원본 행에 Jira 열이 없거나 보관 원본이 없음)을 구분하고 툴팁에 이유를 적는다. 검색창에서 Jira 코드로도 Item을 찾는다.
- 펼친 Item 위쪽의 위험 기준 강조 박스(노란 칸: 등록 건수·분류 칩·기준명·`위험 후보 N대`·`대시보드 위험 후보 보기`)는 제거했다(feature/risk-candidate-reason-ui). 기준 확인은 목록 행의 `위험 기준 N건` 배지 → 판정 팝업에서 한다. 판정 팝업의 `대시보드 위험 후보 보기`는 유지하며, 현재 대시보드 조회 결과의 위험 후보와 겹치는 설비만 대시보드 설비 목록으로 연다. 조회 미적용·범위 밖이면 이동하지 않고 이유를 안내한다.
- 위험 기준 저장 시 기존 관리 저장 흐름이 대시보드·히트맵 판정을 무효화하고, 아이템 목록(배지·`위험 등록된 Item` 필터)과 적용 중인 같은 조회 조건의 위험 판정을 다시 읽는다. 스키마 변경은 없다.
- 검증: `tests/test_item_jira_risk_link.py` 7개 통과(격리 SQLite·합성 자료). 실제 릴리즈노트의 Jira 열 표기 확인은 미실시다.

## 위험 후보 판정 기준 분류 (feature/risk-candidate-reason-ui)

- 위험 후보를 '버전을 썼을 때' 기준으로 두 갈래로 나눠 표시한다. 판정 자체(RiskAssessor)는 바꾸지 않고 규칙 판정 방식만으로 분류한다(`features/risk/schemas.py`의 `RiskKind`).
  - **적용 위험**: 결함 Item(`DEFECT_ITEM`)이 든 버전이나 위험 버전(`DIRECT_VERSION`)을 사용 중이라 위험.
  - **미적용 위험**: 필수 Item(`SAFETY_REQUIRED`)이 그 버전에 적용되지 않아 위험.
- 대시보드 `히트맵`의 위험 후보 배지는 `후보 n` 대신 위험 후보 KPI와 같은 경고 아이콘(`60dbd.svg`) + 대수로 보인다. 툴팁에 적용/미적용 위험 대수를 적고, 판정 근거가 없는 자료는 분류하지 않고 `판정 근거 미연결`로 센다.
- 배지를 눌러 여는 오른쪽 패널의 설비 목록에 `위험 기준` 열(적용 위험/미적용 위험, 근거 없으면 `근거 미연결`)을 더한다. 행을 열면 상세 패널에 `위험 판정 이유` 카드가 분류별로 기준명·PM·버전·판정 문구를 보인다(히트맵 설비 상세 패널도 같은 카드). 적용 위험은 채운 위험색, 미적용 위험은 흰 바탕·위험색 테두리 배지다.
- 미확인은 위험 후보로 분류하지 않고 `미확인` 묶음으로만 보인다. 스키마 변경 없음. 검증: `tests/test_risk_candidate_reasons.py`.

## 저장 호환성과 예외

- SQL 스키마 변경 없이 기존 `risk_rule.target_reference.item_manager` JSON에 표시 정보와 검증된 범위를 보관한다. 기존 재연결 근거는 유지한다. 공통 위험 판정기에도 모델·위치 범위를 적용하므로 관리 화면에만 존재하는 장식용 필터가 아니다.
- 공정 위험/기타는 분류명이다. 사용자가 기존 필수 Item/위험 버전/결함 범위 중 판정 방식을 명시적으로 선택한다. 새 제조 정책을 임의로 추가하지 않는다.
- 저장된 N 그룹이 해당 모델·계열에 우선 적용 중이면 자동 이동으로 이를 덮어쓰지 않고 기준 확인을 안내한다. 적용 근거·버전 순서 미확인도 같은 방식으로 차단한다.
- 미연결·빈 자료·AI 실패·검증 실패는 0대/안전 확정으로 표시하지 않는다. AI 미연결 시 키워드 조회임을 구분한다. AI 후보는 한 계열 500개까지 검증하며 초과 시 원문 키워드 조회를 안내한다.
- 2026-11-07 로컬 DB 읽기 확인: 설비 관측 85대, 릴리즈 0건, Item 0건, 위험 규칙 0건. 실제 Item 화면의 내용 확인에는 릴리즈노트 가져오기·검토·저장이 선행되어야 한다. 이번 작업에서는 로컬 DB에 데이터를 추가하지 않았다.

## 검증 기록

- 팀원 MR `!97`의 소스 `3ef80d5`와 현재 작업 파일 7개는 직접 중복이 없었다. `origin/develop`의 `d2c2008`을 현재 작업 브랜치에 fast-forward pull했다. AI 이어 묻기는 새 ChatPage의 초안 API와 연결했다.
- 최종 신규 검증: `tests/test_item_manager_ver5.py` **18개 통과**. 원본 열/문자 보존, AI ID 위조 거부, 누적 적용, 비동기 응답, 탭/화면 이동, 전역 조건 불변, 위험 범위 미리보기/저장/재로딩, 잘못된 범위 롤백, 취소/중복 저장, 저장 실패/결과 미확인 안내 보존을 검사했다.
- 대화 화면·Item·관리 앱 연결 최종 회귀 **40개 통과**. 별도 Item/누적/배포/내보내기 묶음 **88개 통과**, 버전 화면/개요 묶음 **47개 통과**, 히트맵/설비 상세 탐색·복귀 **3개 통과**를 확인했다. 묶음 간 중복이 있으므로 합산하지 않는다.
- 전체 테스트도 시도했으나 장시간 실행으로 완주 전에 중단했다. 실행 중 발견한 중복 안내 배지의 기존 기대 1건은 VER5 표시 기준에 맞게 수정하고 관련 대화 화면 테스트를 재검증했다. **전체 테스트 통과를 주장하지 않는다.**
- 1600px·1100px·960px에서 합성 데이터로 렌더링하고, 새 18px AI 아이콘과 기존 20px 검색 아이콘의 원본 파일/슬롯/크기를 확인했다. 배지의 원래 셀 글자 겹침, 화살표/문자 깨짐 없이 상태 문구가 읽히는지 검사했다.
