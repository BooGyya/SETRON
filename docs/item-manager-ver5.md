## 화면 구성

탭 없는 한 화면이다(예전 `Item 분석` / `Item 관리` 탭과 위험 기준 관리 탭은 없앴다).

| 영역 | 화면 글자 · 동작 |
| --- | --- |
| 위쪽 도구 | 제목 `검색 결과` · `위험 등록된 Item` 체크 · **SW 계열** 드롭다운 · 검색칸(`기능명·증상 검색`, 왼쪽 돋보기) |
| AI 답변 카드 | 돋보기나 Enter로 검색하면 목록 위에 `AI 답변` 카드가 뜬다 |
| Item 목록 | 머리글 **버전 / 업데이트 내용 / JIRA**. 행 오른쪽에 `위험 기준 N건`(또는 `해제된 기준 N건`) 배지. 아래 쪽 이동 막대와 [다시 불러오기] |
| 펼친 Item | 행을 누르면 그 자리에서 펼친다. `설비별 적용 현황`(`전체 Site` · `전체 상태` 필터, 적용/미적용/미확인 대수 배지, 설비 표) · [현황 접기] · **[위험 기준 보기]** · **[위험 기준 등록]**(이 계열에 사용 중 기준이 있으면 [위험 기준 추가]) |

- 선택한 계열에 릴리즈노트 Item이 없으면 목록 대신 `… 에 연결된 릴리즈노트 아이템이 없습니다.` / `데이터 가져오기에서 릴리즈노트를 가져오면 여기에 표시됩니다.`를 보인다.
- 검색칸에 글자를 치면 목록을 바로 거른다(Jira 코드로도 찾는다). 돋보기 · Enter는 AI 답변을 만든다. `위험 등록된 Item` 체크는 목록만 다시 거른다.
- 펼친 Item의 설비 표 열: 설비 · Site · Line · 모델 · 적용 상태 · 버전 · 비고. 행을 누르면 설비 상세로 간다.

### AI 답변 카드

- 출처 표시: `실제 AI 응답` / `AI 미연결 · 키워드 검색` / `테스트 응답 · 실제 AI 아님` + 관측일.
- 왼쪽 `포함 버전 · 원본 근거`(`최초 확인 포함` / `포함 확인`), 오른쪽 `적용 현황 · 물리 설비 중복 제거`(적용 / 판정 대수, 미적용 설비, 미확인 · 대상 외 · HPA 제외).
- 아래 버튼: [AI 분석에서 이어서 묻기] · [히트맵에서 보기] · [대시보드에서 보기]. 버튼을 누를 때만 다른 화면의 조회 조건을 바꾼다.
- AI는 관련 Item을 찾는 데만 쓴다. 포함 버전 · 대수 · 적용률은 저장된 릴리즈 · 관측으로 계산한다. AI 후보는 한 계열 500개까지 검증한다.

## 위험 기준

### 등록 · 수정 창 (`위험 기준 등록` / `위험 기준 수정`)

| 입력 | 내용 |
| --- | --- |
| 관련 아이템 검색 · 관련 릴리즈 계열 · 관련 릴리즈노트 Item | 펼친 Item에서 열면 Item이 고정된다 |
| 위험 기준명 | 비워 두면 계열 · 기준 버전 · 판정 기준으로 이름을 제안한다 |
| **기준 버전** | 그 계열의 릴리즈 버전 하나(순서가 없으면 `· 순서 미확인`) |
| **위험 판정 기준** | **버전 미만** / **버전 일치** / **버전 초과** |
| Site · Line · 설비군 | 위험 대상 범위. 설비군은 하나 이상 골라야 한다 |
| 메모 (선택) | 영향 계산에 쓰지 않는다 |

- 판정 기준 저장 값(`features/risk/schemas.py` `RuleType`): 버전 미만 `VERSION_BELOW` · 버전 일치 `DIRECT_VERSION` · 버전 초과 `VERSION_ABOVE`. 미만 · 초과는 릴리즈 순서로 비교하고, 순서가 미확인이거나 중복이면 `미확인`으로 둔다.
- 입력을 바꾸면 영향 미리보기를 자동으로 다시 계산한다(`위험 적용 대상 N건`, 영향 설비 표: 설비 · 위치 · SW 버전). 계산이 끝나야 [등록]이 켜진다.
- 아래 버튼: **[다시 계산] / [취소] / [등록]**(수정일 때 [수정 저장]).
- 예전에 저장한 `SAFETY_REQUIRED`(환경안전 필수) · `DEFECT_ITEM`(결함 Item 범위) 기준은 수정 창에서 기존 조건을 그대로 유지하고 안내 줄에 보인다.
- 저장은 기존 관리 저장 경계(`ItemRiskPage` → `RiskRuleSaveController`)로 한다. 실패는 `저장 실패 · 기존 자료 유지 …`, 결과 미확인은 `저장 결과 미확인 · 중복 등록하지 말고 …`로 남는 안내를 보인다.

### 위험 기준 목록 · 판정 창

- [위험 기준 보기] → `위험 기준 목록` 창: `등록된 위험 기준 N건 · 적용됨 M건`, 표(위험 기준명 · 기준 버전 · 판정 기준 · 상태 `적용됨`/`해제됨`), [닫기]. 행을 고르면 판정 창이 열린다.
- 판정 창(`위험 기준 판정`): 위험 기준명 · 기준 버전 · 판정 기준, `위험 적용 대상 N건`, Site · Line · 설비군 필터, 표(설비 · 위치 · 판정 · SW 버전). 판정은 `위험 후보` / `미확인` / `위험 없음`.
- 판정 창 버튼: **[해제]**(해제된 기준이면 **[다시 사용]**) · **[수정]** · **[삭제]** · **[닫기]**.
  - [해제] / [다시 사용]: 확인 창(`위험 기준을 해제할까요?` / `위험 기준을 다시 사용할까요?`)에 `적용 대상 N건`(계산 불가면 `적용 대상 확인 불가`)과 [취소] / [해제]·[다시 사용]. 기준 행은 지우지 않고 `is_enabled`만 바꾼다. 완료는 `기준을 해제했습니다.` / `기준을 다시 사용합니다.`(몇 초 뒤 사라짐).
  - [수정]: 같은 등록 창을 수정 모드로 연다.
  - [삭제]: `위험 기준 '…'을(를) 삭제할까요?` 확인 뒤 그 기준 한 건만 지운다.
  - DB 연결이 없으면 해제 · 다시 사용을 할 수 없다.
- 저장 뒤에는 관리 저장 갱신 경로(`after_management_save`)로 대시보드 위험 후보 · 히트맵 · 아이템 목록(배지 · `위험 등록된 Item` 필터)을 다시 읽는다.
- `위험 기준 N건` 배지와 등록 필터는 사용 중 기준만 센다. 사용 중 기준이 없고 해제된 기준만 있으면 중립색 `해제된 기준 N건` 배지를 둔다. 배지는 표시만 하고, 기준 확인은 펼친 영역의 [위험 기준 보기]에서 한다.

### 위험 후보 분류 (적용 위험 / 미적용 위험)

- 판정(`RiskAssessor`)은 바꾸지 않고 규칙 종류로만 나눈다(`RiskKind`).
  - **적용 위험**: `DEFECT_ITEM` · `DIRECT_VERSION` · `VERSION_BELOW` · `VERSION_ABOVE`. 위험한 버전 · Item을 쓰고 있어 위험.
  - **미적용 위험**: `SAFETY_REQUIRED`. 필수 Item이 적용되지 않아 위험.
- 대시보드 위험 후보 배지 툴팁, 설비 목록의 `위험 기준` 열, 설비 상세의 `위험 판정 이유` 카드가 이 분류를 쓴다. 근거가 없으면 `판정 근거 미연결`, 미확인은 `미확인` 묶음으로 따로 보인다.

## Jira 코드 (목록의 JIRA 열)

- DB `item.jira_code`에 저장된 값을 먼저 쓴다(저장된 NULL도 '없음'으로 본다). 이 저장 열이 없던 이전 자료만 가져오기 때 보관한 원본(`import_batch.raw_data`)에서 Item 출처(`source_reference`)가 가리키는 행을 읽는다(`ui/item_data.py` `jira`, `features/item/original.py` `item_jira`). 코드를 만들거나 고치지 않는다.
- 원본에서 읽을 때 열은 시트마다 하나 정한다(11-13, 릴리즈노트 가져오기와 같은 규칙). 설비군마다 머리글이 달라서(O2 `Issue` · O5 `JIRA` · O3 `JIRA ID` · C4 `REMARK`) Jira 열을 먼저, 없으면 비고 열을 쓴다. 이름으로 못 찾으면 Item 행 절반 이상에 `ETOJ-1234` 모양이 있는 열을 쓴다.
- 코드가 없으면 `Jira 없음`(칸이 비었거나 `-`)과 `Jira 미확인`(Jira 열이 없거나 보관 원본이 없음)을 구분한다.

## 데이터 경계

- 동일 계열에서 최초 포함된 Item은 확인된 후속 버전에도 누적 적용된다(11-07 사용자 확인). 최초 포함 이전은 미적용이다.
- 순서 미확인 · 중복 · 계열/모델 범위 미확인은 추정하지 않는다. 미연결 · 빈 자료 · AI 실패는 0대/안전 확정으로 표시하지 않는다.
- 검색 · 화면 이동 · 미리보기만으로 DB를 바꾸지 않는다. 위험 기준은 SQL 스키마 변경 없이 `risk_rule`과 `target_reference.item_manager` JSON(표시 이름 · 범위 · 메모)에 저장한다.
- 데이터 관리 › 릴리즈노트에는 위험 열 · 버튼이 없다. 위험 기준은 아이템 매니저에서만 다룬다.
