# 데이터 관리 화면 (11-10 개편, 11-11 2차 수정)

사이드바 **데이터 관리** 하나로 기존 `버전 관리`·`관리 데이터` 메뉴를 대신한다. 두 화면은 다른 화면의 내부 이동(레코드 열기, Item 위험 등록 저장 등)에 계속 쓰이므로 등록은 그대로 두고 사이드바에서만 숨겼다 (`main_window.HIDDEN_MENUS`).

## 탭 구성 (고정)

| 탭 | 하위 | 하는 일 | 쓰는 기능 |
|---|---|---|---|
| 설비현황 | 현황표 | 가져온 엑셀 시트를 원래 열·행 번호로 보여 주고, DB 값과 연결된 칸을 고치면 바로 저장한다. 고른 설비의 행을 지운다 | `DataAdminService.status_sheets / sheet_grid / delete_rows` + 관리 저장 `gateway.save` |
| | 설비 | 설비군 목록(개조형도 상위 설비군 아래 한 줄씩), 설비 목록(설비 ID · 모델 · Site · Line), **설비군 추가** | `equipment_overview / create_group` |
| | 위치 | Site → Fab → Line 트리(관측 Site + 등록 Site), 소속 설비, **Site 추가(DB 저장)** | `equipment_overview / sites / add_site` |
| | 가져온 엑셀 삭제 | 데이터 가져오기에 있던 기준일·Site 단위 삭제 화면을 그대로 옮김 (한 행씩 지우기는 현황표) | `ImportDeletePage` (같은 객체) |
| 릴리즈노트 | — | 계열 목록(개조형은 상위 계열 아래), 버전 줄 아래 Item 줄이 붙은 표. 칸을 고치면 바로 저장 | `release_families / release_rows` + `gateway.save` |
| 변경 이력 | — | 수정 · 등록 · 삭제 기록을 수정 일시 · 구분 · 수정 파일 · 시트·셀 · 대상 · 항목 · 수정 전 · 수정 후로 한 줄에 보인다 | `history` (MANUAL 입력 작업) |

## 정한 것

- **고치기·더하기·지우기는 바로 DB에 반영**한다 (11-11). [수정 저장] 버튼과 '저장할까요?' 확인은 없고, 칸 편집을 마치면 그 칸만 저장한다(저장 중 노란색 → 저장됨 초록색). 저장 중에 고친 칸은 앞 저장이 끝나면 이어서 저장한다. 되돌릴 수 없는 **행 삭제만** 한 번 묻는다. 저장하지 못하면 칸을 DB 값으로 되돌리고 이유를 보인다.
- 저장 직전 최신 검토 지문(revision)으로 묶어 다른 곳의 변경과 충돌하면 거부된다. 저장·등록·삭제가 끝나면 `saved`를 보내 앱이 조회 선택지와 대시보드·히트맵을 DB에서 다시 읽는다(`after_management_save`).
- **현황표 표시**: 값이 하나도 없는 줄(엑셀 빈 줄)은 빼고, 행 번호는 엑셀 그대로 둔다. 연결된 첫 데이터 행 위는 머리글(굵게·회색 바탕)이고, 첫 칸에만 값이 있는 제목 줄은 한 줄로 펼친다. 열이 적으면 남는 폭을 열마다 나눠 표를 채운다. DB 칸이 없는 출처(가져올 때 남긴 설비군 이름 등)는 칸을 연결하지 않고 원본 값을 그대로 보인다 (11-11, 1행이 빈칸으로 보이던 원인).
- **현황표 행 삭제** (11-11): 고른 칸이 속한 설비의 그 기준일 관측을 PM → SW → 설비 현황 순서로 한 트랜잭션에서 지운다. 설비 호기와 가져온 원본 셀은 남기고, 지운 칸은 '삭제됨'(회색 취소선)으로 보인다. 지운 칸 위치·값은 MANUAL 기록 `management_delete`에 남아 변경 이력에 '삭제'로 나온다. 엑셀 한 장(기준일·Site)을 통째로 지우는 것은 '가져온 엑셀 삭제'에서 한다.
- **설비군 추가**는 `equipment_group`에 저장한다. 조회 선택지는 `GROUP_MODELS` 이름으로 묶고, 거기에 없는 개조형은 상위 설비군에 함께 묶으며, 거기에 없는 기본형(POLY·OXIDE·KCTC, 분석 대상)은 `group-<ID>` 선택지로 같은 분류 뒤에 넣는다 (`database_source.group_keys / registered_group_options`, 11-11). 그래서 추가한 설비군이 대시보드·히트맵·리플레이 설비군에 보인다.
- **Site 추가는 DB에 저장**한다 (11-11). Site 테이블이 없어 관리 설정 `app_setting`의 `registered_sites.v1`(`{"sites": [...]}`)에 이름 목록으로 둔다. 조회 Site 선택지는 관측된 Site에 이 목록을 더해 만든다(설비가 없으면 칸은 `—`). 관측 Site나 이미 등록한 이름(대소문자 무시)은 거부한다. 설비가 어느 Site에 있는지는 여전히 가져온 현황표로 정해진다.
- **위험 지정은 아이템 매니저에서만** 한다 (11-11). 릴리즈노트 탭에서 위험 열과 [위험 지정] 버튼을 뺐다.
- **시각 표시**: DB의 `imported_at`은 DB 서버 시계(개발용 Docker는 UTC)로 기록되므로, 읽을 때 `SELECT NOW()`와 이 PC 시계의 차이(15분 단위)를 더해 PC 시각으로 보인다 (`clock_offset`, 11-11).
- **파일 이름 보관**: 앞으로 가져오는 자료는 `import_batch.raw_data`의 `[파일]` 키(`WORKBOOK_KEY`)에 파일 이름을 함께 보관한다. 엑셀 시트 이름에는 `[` `]`를 쓸 수 없어 시트와 겹치지 않는다. 시트 이름을 세는 곳(삭제 목록 `_sheet`, 재가져오기 비교)은 이 키를 뺀다. 그 전에 가져온 자료는 '파일 이름 없음'으로 보인다.
- 현황표에서 SW 버전을 고치면 릴리즈 연결(`release_version_id`)을 비워 저장 후 다시 판정한다. Site·기준일 칸은 고칠 수 없다.
- 릴리즈노트 '적용 모델'은 설비군 이름을 쉼표로, 날짜는 YYYY-MM-DD로 적는다(틀리면 저장하지 않고 칸을 되돌린다).

## 남은 것

- 릴리즈노트 버전·Item의 삭제·신규 등록은 화면에 없다(기존 서비스 미노출). 다시 가져오면 계열 전체가 교체된다.
- 등록한 Site·설비군의 이름 변경·삭제는 아직 없다.
- 위험 지정의 영향 버전은 시작~해제 범위만 된다(버전 목록 지정 없음).
