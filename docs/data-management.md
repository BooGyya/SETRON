# 데이터 관리 화면 (11-10 개편, 11-11 2~5차 수정)

사이드바 **데이터 관리** 하나로 기존 `버전 관리`·`관리 데이터` 메뉴를 대신한다. 다른 화면의 내부 이동에 쓰이는 화면은 등록은 그대로 두고 사이드바에서만 숨겼다 (`main_window.HIDDEN_MENUS`).

## 탭 구성 (고정)

| 탭 | 하위 | 하는 일 | 쓰는 기능 |
|---|---|---|---|
| 설비현황 | 현황표 | 가져온 엑셀 시트를 원래 열·행 번호로 보여 준다. 칸 수정 · 행 추가 · 행 삭제를 모아 [저장]으로 한꺼번에, [되돌리기] | `DataAdminService.status_sheets / sheet_grid / apply_rows / undo_rows` + 관리 저장 `gateway.save` |
| | 설비 | 설비군 목록(분류는 묶음 첫 줄에만, 개조형도 한 줄씩), 설비 목록(설비 ID · 모델 · Site · Line), **설비군 추가** | `equipment_overview / create_group` |
| | 위치 | Site → Fab → Line 트리(관측 Site + 등록 Site), 소속 설비, **Site 추가 → 빈 현황표 만들기** | `equipment_overview / sites / add_site / create_sheet` |
| | 가져온 엑셀 삭제 | 종류 · Site · 기간을 고르고 [검색]을 누르면 그 조건의 가져온 엑셀만 목록에 뜨고, 지울 것을 직접 골라 기준일·Site 단위로 지운다 (한 행씩은 현황표) | `ImportDeletePage` (같은 객체) |
| 릴리즈노트 | — | 계열 목록 · 최신 버전이 위인 표. 칸 수정 · 버전/Item 추가 · 삭제 · Item 순서를 모아 [저장]으로 한꺼번에, [되돌리기] | `release_families / release_rows / apply_release / undo_release` + `gateway.save` |
| 변경 이력 | — | 기본 열(수정 일시 · 구분 · 대상 · 항목 · 수정 전 · 수정 후)만 보이고, 줄을 누르면 오른쪽에서 세부 정보가 나온다 | `history` (MANUAL 입력 작업) |

## 정한 것

### 현황표 (11-11 4차)

- **칸 수정 · 행 추가 · 행 삭제를 모아 두었다가 [저장]으로 한꺼번에** 반영한다(노란색 수정 · 분홍색 새 행의 빈 필수 칸 · 빨간 칸 삭제 예정). 저장 전에는 DB에 아무것도 쓰지 않는다. 행 삭제가 있으면 저장할 때 한 번 묻고, 새 행에 없는 설비군이 있으면 그때 분류를 골라 등록한다.
  - 저장 순서: 새 설비군 등록 → 칸 수정(관리 저장, 저장 직전 검토 지문으로 묶어 다른 곳의 변경과 충돌하면 거부) → 행 추가 · 삭제(`apply_rows`, 한 트랜잭션). 삭제 예정인 행의 칸 수정은 저장하지 않는다.
  - 칸 수정은 저장됐는데 행 추가 · 삭제가 거부되면(예: 같은 기준일 중복 호기) 칸 수정만 반영된 상태로 오류를 보인다. 바뀐 내용은 화면에 남아 고쳐서 다시 저장할 수 있다.
- 저장하지 않은 변경이 있는데 다른 시트를 고르면 저장 · 버리기 · 취소를 묻는다. 저장한 뒤에는 묻지 않는다.
- **[되돌리기]**는 누를 때마다 바로 앞 단계 하나를 되돌린다: 저장 전 칸 수정 → 이전 글자, 새 행 칸 → 이전 글자, 새 행 → 없앰, 삭제 표시 → 풂, 마지막 저장 → 그 저장 전체(추가한 행 지우기 · 지운 행 되살리기 `undo_rows`, 칸 수정은 저장 전 값으로 다시 저장).
- **행 추가**: [＋ 행 추가]로 표 맨 아래에 새 행(행 번호 `＋n`)을 만든다. 호기 · 설비군(모델) · SW 버전이 필수, Line은 선택. Site · 기준일은 현황표에서 정한다. 엑셀 원본 셀은 바꾸지 않고, 새 칸 위치를 출처로 남긴다.
  - SW 계열은 같은 현황표 · 같은 설비군 설비가 쓰는 계열을 따른다. 없으면 설비군(또는 상위 설비군)의 계열 중 하나(파운드리 라인 여부, UI 표기 없으면 통합UI)로 정하고, 하나로 정할 수 없으면 거부한다. **계열이 하나도 없는 새 설비군이면 설비군 이름으로 계열을 만든다**(릴리즈 노트가 없어 '정보 부족'으로 보인다).
  - 열 구성(어느 열이 Line · 설비군 · 호기 · SW 버전인지)은 이미 연결된 칸에서 정한다. 알 수 없는 시트는 행 추가를 막는다.
- **행 삭제**: 고른 칸이 속한 설비의 그 기준일 관측을 PM → SW → 설비 현황 순서로 지운다. 설비 호기와 가져온 원본 셀은 남기고, 지운 칸은 '삭제됨'(회색 취소선)으로 보인다. 되살릴 수 있게 지운 행 전체를 MANUAL 기록 `management_delete`에 남긴다.
- **정렬**: 데이터 행은 기본으로 Line → 설비군 → 호기 순(숫자는 숫자로 비교)이고, 표 위에 지금 정렬 기준을 적는다. 열 제목을 누르면 그 열 오름차순 → 내림차순 → 기본 정렬 순으로 바뀐다(제목에 ▲/▼). 행 번호는 엑셀 그대로 둔다.
- **표시**: 값이 하나도 없는 줄은 빼고, 원본 엑셀의 순번 열(머리글 No · 번호 · 순번, DB에 저장하지 않는 값)은 숨긴다. 연결된 첫 데이터 행 위는 머리글(굵게 · 회색 바탕), 첫 칸에만 값이 있는 제목 줄은 한 줄로 펼친다. DB 칸이 없는 출처(가져올 때 남긴 설비군 이름 등)는 칸을 연결하지 않는다.
- 현황표에서 SW 버전을 고치면 릴리즈 연결(`release_version_id`)을 비워 저장 후 다시 판정한다. Site · 기준일 칸은 고칠 수 없다.

### Site · 설비 추가 흐름 (11-11 확정)

1. 새 사업장: 위치 › [＋ Site] → DB 관리 설정(`app_setting` `registered_sites.v1`)에 저장 → 대시보드·히트맵 Site 선택지에 보임 → "빈 현황표를 만들까요?" → 기준일 입력 → 빈 현황표(직접 입력, 머리글 No · Line · 설비군 · 설비호기 · Version) 생성 → 현황표 탭에서 열림.
2. 기존 Site에 설비: 현황표에서 그 Site · 기준일 시트를 골라 [＋ 행 추가].
3. 설비군 추가는 설비 탭에서도 할 수 있지만, 보통은 행 추가 때 그 자리에서 등록한다.

빈 현황표는 `import_batch`(MANUAL)의 `raw_data`에 시트 머리글과 `[현황표]` 키(Site · 기준일)를 넣어 만든다. 엑셀 시트 이름에는 `[` `]`를 쓸 수 없으므로 `[`로 시작하는 키는 시트가 아니다(`sheet_names`). 같은 Site · 기준일 현황표가 이미 있으면 만들지 않는다.

### 조회 선택지

- **설비군 추가**는 `equipment_group`에 저장한다. 조회 선택지는 `GROUP_MODELS` 이름으로 묶고, 거기에 없는 개조형은 상위 설비군에 함께 묶으며, 거기에 없는 기본형(POLY·OXIDE·KCTC, 분석 대상)은 `group-<ID>` 선택지로 같은 분류 뒤에 넣는다 (`database_source.group_keys / registered_group_options`).
- **Site**: 조회 Site 선택지는 관측된 Site에 등록 Site를 더해 만든다(설비가 없으면 칸은 `—`). 관측 Site나 이미 등록한 이름(대소문자 무시)은 거부한다.
- 저장 · 등록 · 삭제가 끝나면 `saved`를 보내 앱이 조회 선택지와 대시보드·히트맵을 DB에서 다시 읽는다(`after_management_save`).

### 가져온 엑셀 삭제 (11-11 4차)

- 화면에 들어올 때 목록을 읽어 두고, 종류 · Site · 기간(또는 계열)을 고른 뒤 '직접 선택' 오른쪽의 **[검색]**을 눌러야 그 조건의 가져온 엑셀이 2번 목록에 보인다. 조건을 바꾸면 목록을 비우고 다시 [검색]을 기다린다. 기간을 비우면 기간 제한이 없다.
- **자동 선택은 하지 않는다.** 지울 것을 체크하거나 머리 체크로 보이는 것 전체를 고른다.
- 열은 기준일 · Site · 시트 · 설비/행 · 저장일 · 저장 방식 · 상태로 나눴다(릴리즈 노트는 Site 열 숨김). '남는 기준일'은 목록에 보이는 것이 아니라 같은 종류의 저장 자료 전체에서 센다.
- 저장일은 PC 시각으로 보인다(아래 시각 표시).

### 릴리즈노트 (11-11 5차)

- **최신 버전이 위**(버전 순서 내림차순, 순서가 없는 버전은 맨 아래). 왼쪽 줄 번호는 1부터 매긴다.
- **칸 수정 · 버전/Item 추가 · 삭제 표시 · Item 순서를 모아 두었다가 [저장]으로 한꺼번에** 반영한다(노란색 저장 전 · 빨간 칸 삭제 예정). 저장 전에는 DB에 아무것도 쓰지 않는다. 삭제가 있으면 저장할 때 한 번 묻는다. 저장하지 않은 변경이 있는데 다른 계열을 고르면 저장 · 버리기 · 취소를 묻는다.
  - 저장 순서: 칸 수정(관리 저장, 검토 지문 충돌 시 거부) → 추가 · 순서 · 삭제(`apply_release`, 한 트랜잭션). 삭제 예정인 줄의 칸 수정은 저장하지 않는다.
  - 날짜는 YYYY-MM-DD, 적용 모델은 설비군 이름을 쉼표로, '전체'는 전체 설비(ALL)다. 틀리면 칸을 되돌리고 저장 목록에 넣지 않는다.
- **[되돌리기]**: 저장 전에는 바로 앞 단계(칸 수정 · 추가 · 삭제 표시 · 순서) 하나씩, 저장 뒤에는 마지막 저장 전체를 되돌린다(`undo_release`: 추가한 버전 · Item 지우기, 지운 버전 · Item 되살리기, 바꾼 순서 되돌리기 + 칸 수정은 저장 전 값으로 다시 저장). 되살린 버전 · Item은 새 ID로 다시 들어가며, **삭제 때 '연결 미확인'이 된 위험 지정 연결은 되살리지 않는다**.
- **버전 추가**: 새 버전은 맨 위에 보이고, 저장하면 순서 맨 끝(기존 최대 + 10)으로 들어간다. 같은 원문인데 릴리즈 연결이 없던 설비 SW는 새 버전에 잇는다.
- **Item 추가**: 고른 줄의 버전 맨 뒤에 내용 · 적용 모델을 더한다(새 버전에도 가능). 번호(No)는 적지 않고 맨 뒤 번호 다음으로 매긴다. 적용 모델을 비우면 전체 설비(ALL).
- **Item 순서**: Item 줄을 끌어 같은 버전 안의 다른 줄에 놓으면 그 자리로 옮기고(No 칸 노란색), 저장할 때 번호를 1부터 다시 매긴다. No 칸은 직접 고치지 않는다.
- **삭제**: [선택 Item 삭제]는 그 버전에서 Item 연결을 지우고, 다른 버전에 쓰이지 않는 Item이면 Item도 지운다. [선택 버전 삭제]는 버전과 그 Item 연결을 지운다. 저장 전 새 줄은 바로 없앤다. 위험 지정이 가리키던 버전 · Item은 근거를 남기고 '연결 미확인'으로 바꾸고(`StorageTransaction.delete_release_*`), 그 버전을 쓰던 설비 SW의 릴리즈 연결은 DB 규칙대로 비워진다. 그 버전으로 정한 목표 N은 다시 정해야 한다. 되살릴 수 있게 지운 버전 · Item · 연결 전체를 MANUAL 기록 `management_delete_release`에 남긴다.
- **위험 지정은 아이템 매니저에서만** 한다. 이 탭에는 위험 열·버튼이 없다.

### 변경 이력 (11-11 4차)

- 기본 열(수정 일시 · 구분 · 대상 · 항목 · 수정 전 · 수정 후)만 넓게 보이고, 줄을 누르면 대시보드 설비 상세처럼 창 오른쪽에서 세부 정보 패널(`SideDrawer`)이 나온다(구분 · 전체 수정 일시 · 파일 · 시트 · 셀 · 수정 전 → 후). Esc · 접기 · 바깥 클릭이나 다른 탭으로 가면 닫힌다.
- 목록의 일시는 올해면 'MM-DD HH:MM'으로 짧게 보인다. 탭에 들어올 때마다 DB에서 다시 읽는다([새로 읽기] 버튼 없음).
- 구분: 수정(칸 · Item 순서) · 등록(설비군 · Site · 현황표 · 릴리즈 버전 · Item · 위험 지정) · 추가(현황표 행) · 삭제(현황표 행 · 릴리즈 버전 · 릴리즈 Item, 되돌리기로 지운 것은 '추가 취소') · 되돌리기(지운 현황표 행 · 릴리즈 줄 되살림).

### 공통

- **열 폭**: 모든 표는 열 경계를 끌어 폭을 바꿀 수 있고, 사람이 바꾼 폭은 이 PC 설정(`QSettings`, `data_management/columns/<표>`)에 기억해 다음에도 그대로 연다. 기억한 폭이 없으면 내용 폭으로 맞춘다.
- **시각 표시**: DB의 `imported_at`은 DB 서버 시계(개발용 Docker는 UTC)로 기록되므로, 읽을 때 `SELECT NOW()`와 이 PC 시계의 차이(15분 단위)를 더해 PC 시각으로 보인다 (`clock_offset`).
- **파일 이름 보관**: 앞으로 가져오는 자료는 `import_batch.raw_data`의 `[파일]` 키(`WORKBOOK_KEY`)에 파일 이름을 함께 보관한다. 그 전에 가져온 자료는 '파일 이름 없음'으로 보인다.

## 남은 것

- 등록한 Site · 설비군의 이름 변경 · 삭제는 아직 없다.
- 현황표에서 '설비군' 칸(모델)을 고치면 모델 표기만 바뀌고 설비군 연결(`group_id`) · SW 계열은 그대로다(가져오기 때 정한 값).
- 새 설비군에 자동으로 만든 SW 계열은 릴리즈 노트를 가져오면 그 계열 이름과 맞춰야 한다.
- 위험 지정의 영향 버전은 시작~해제 범위만 된다(버전 목록 지정 없음).
