# 데이터 관리 화면 (11-10 개편, 11-11 2~6차 · 11-12 수정)

기준: 2026-11-16, develop f0cfc8d. 코드: `ui/data_management_page.py`, `ui/import_delete.py`(가져온 엑셀 삭제), `features/data_admin/`.

사이드바 **데이터 관리** 하나로 기존 `버전 관리`·`관리 데이터` 메뉴를 대신한다. 다른 화면의 내부 이동에 쓰이는 화면은 등록은 그대로 두고 사이드바에서만 숨겼다 (`main_window.HIDDEN_MENUS`).

## 탭 구성 (고정)

화면의 생산 분류·선택 목록·안내·계열 표시 이름은 `Memory`와 `Foundry`로 통일한다. 편집 후 저장·필터에는 기존 코드 `MEMORY`와 `FOUNDRY`를 사용하며, 한글 입력과 DB 원본은 보존한다.

## 정한 것

### 현황표 (11-11 6차: DB 값 기준)

- **DB에 들어간 값을 가져오기 검토 표(AI 추출 결과)와 같은 열 · 순서로** 보인다 (11-16): 기준일 · Site · Line · 대분류 · 설비군 · 모델명 · Memory/Foundry · 설비 호기 · PM · 공정 · SW 계열 · SW 버전 · UI 구분 · 형상 · 개조 정보. 대분류는 데이터 관리에만 있는 열이다(새 설비군 등록용). Engine · EPD 버전은 DB에 칸이 없어 두지 않고(ERD 그대로), Inline/Cluster는 가져오기처럼 숨긴다.
- **한 줄 = PM 하나**(가져오기 표와 같음). PM이 없는 설비는 SW 하나가 한 줄, SW도 없으면 설비 현황 한 줄이다(`DataAdminService.sheet_rows`, `SheetRow.pm_id`). PM 줄의 설비군 · SW 계열 · SW 버전은 그 PM의 값이다. PM 칸은 늘 보인다.
- **현황표 하나 = 입력 작업 · 기준일**이다. 시연 seed(`database/seed_source.py`, demo_seed.v2 · 팀 Docker 시연 DB)는 입력 작업 하나에 기준일 6개(6개월)가 들어 있어, 목록과 표 · 행 추가를 기준일별로 가른다 (11-12, `sheet_rows(batch_id, base_date)` · `apply_rows(..., base_date=)`).
- 원본 시트는 가져오기 형식(맨 위 키가 시트)과 시연 seed 형식(`sheets` 안, 파일 이름은 `source_workbook`) 둘 다 읽는다(`sheet_cells`). 시트가 여럿이면 원본 칸 주소에 시트 이름을 붙인다(예: `P3-S5!D5`).
- 칸에 마우스를 올리면 그 값이 온 원본 셀 주소와 원본 값이 보인다(`sources / source_values`). 앱에서 고친 값은 원본 엑셀에 반영되지 않는다. 엑셀 원본 시트를 보는 [원본 보기]는 두지 않는다(11-11 요청으로 삭제, `sheet_grid`는 서비스에만 남음).
- **칸 수정 · 설비군 변경 · 행 추가 · 행 삭제를 모아 두었다가 [저장]으로 한꺼번에** 반영한다(노란색 수정 · 분홍색 새 행의 빈 필수 칸 · 빨간 칸 삭제 예정). 행 삭제는 설비 단위다(PM 줄 하나를 골라도 그 설비의 모든 줄). 저장 전에는 DB에 아무것도 쓰지 않는다. 행 삭제가 있으면 저장할 때 한 번 묻고, 새 행에 없는 설비군이 있으면 그때 분류를 골라 등록한다.
  - 수정 대상: 호기 → `equipment.equipment_code`, Line · 모델명 · 메모리/파운드리 · **공정 · 형상 · 개조 정보** → `equipment_snapshot`(공정 `process_name`은 관리 저장 수정 가능 칸에 11-16 추가), SW 버전 · **SW 계열** → `equipment_version`(릴리즈 연결 `release_version_id`는 비워 다시 판정). 같은 설비의 여러 줄(PM · SW)은 Line · 공정 등 설비 값을 함께 쓴다.
  - **PM 줄**: 설비군 · SW 계열 · SW 버전을 `equipment_pm`으로 관리 저장한다(관리 저장이 같은 값끼리 SW를 나누고 합치며, 설비 현황 설비군은 PM 설비군이 하나면 그 값, 여럿이면 비움). PM 설비군을 바꾸면 SW 계열이 새 설비군의 계열이 아닐 때 Memory/Foundry에 맞는 계열 하나를 고르고, 정할 수 없으면 직접 고르게 한다. **PM 이름은 날짜 간 같은 PM을 잇는 고정 위치라 저장된 줄에서는 고치지 않는다**(관리 저장 규칙 `test_identity_site_and_original_fields_are_immutable`).
  - **SW 계열**은 그 설비군 · 상위 설비군의 계열 중에서 고르고(`SheetRows.families`), **UI 구분은 고른 계열을 따라 보인다**(C3 구UI ↔ 통합UI는 SW 계열을 바꾼다). 기준일 · Site · 대분류 · UI 구분은 표에서 고르지 않는다.
  - **설비군 변경**(PM 없는 설비, `apply_rows(regroup=...)`): 설비 현황의 `group_id`를 바꾸고, 모델명을 새 설비군 이름으로, SW 계열이 새 설비군(또는 상위 설비군)의 것이 아니면 새 설비군의 계열로 바꾸며 같은 원문 릴리즈에 다시 잇는다. PM 설비는 위 'PM 줄'처럼 PM마다 고친다.
  - 설비군 · Line · 메모리/파운드리 칸은 목록에서 고른다(Line은 새 이름도 적을 수 있음). 없는 설비군을 적거나 호기 · SW 버전을 비우면 칸을 되돌린다.
  - **대분류 · 모델명은 설비군에서 자동**이다 (11-12). 대분류(POLY · OXIDE · KCTC)는 설비군의 값(`equipment_group.category`)이라 줄마다 고치지 않고(설비 탭에서 관리), 모델명은 설비군 이름을 따라간다. 대시보드의 '분류' 필터(메모리/파운드리)와 헷갈리지 않게 '대분류'라고 부른다.
  - 모델명이 **다른 설비군을 가리키는** 줄(번역표 `find_candidate` 기준, 예: 설비군 M-C3인데 모델명 M-C4)만 빨간 글자로 보이고, 그 칸에서만 설비군 이름으로 맞출 수 있다. 엑셀 원문 모델명('M-C4(DFB)', 'M-C3 (통합UI)', '5각 Cluster O2')은 같은 설비군이라 맞는 값이다 (`SheetRow.model_mismatch`).
  - **처음 보는 라인**(이 Site에도 다른 Site에도 없는 Line)은 [저장] 때 **그 줄의 메모리/파운드리로** 새 라인을 함께 등록한다(묻는 창 없음, 11-12). 그 줄의 메모리/파운드리가 비었거나 같은 새 라인의 줄끼리 다르면 저장을 막고 안내한다(새 행이면 그 칸이 분홍 필수 칸). 등록은 되돌리기로 지우지 않는다(설비군 등록과 같음). Line 목록에는 이 Site 라인과 이번에 적은 라인이 보인다.
  - 저장 · 오류 안내 줄은 버튼 바로 아래에 보인다 (표 아래에 있으면 저장이 막힌 이유가 보이지 않았다).
  - 저장 순서: 새 설비군 등록 → 칸 수정(관리 저장, 저장 직전 검토 지문으로 묶어 다른 곳의 변경과 충돌하면 거부) → 행 추가 · 삭제 · 설비군 변경(`apply_rows`, 한 트랜잭션). 삭제 예정인 행의 칸 수정은 저장하지 않는다.
  - 칸 수정은 저장됐는데 행 추가 · 삭제가 거부되면(예: 같은 기준일 중복 호기) 칸 수정만 반영된 상태로 오류를 보인다. 바뀐 내용은 화면에 남아 고쳐서 다시 저장할 수 있다.
- 저장하지 않은 변경이 있는데 다른 현황표를 고르면 저장 · 버리기 · 취소를 묻는다. 저장한 뒤에는 묻지 않는다.
- **되돌리기 아이콘(Ctrl+Z)**은 누를 때마다 바로 앞 단계 하나를 되돌린다(되돌린 단계는 다시 실행 아이콘(Ctrl+Y · Ctrl+Shift+Z)으로 다시 적용): 저장 전 칸 수정 → 이전 값, 새 행 칸 → 이전 글자, 새 행 → 없앰, 삭제 표시 → 풂, 마지막 저장 → 그 저장 전체(`undo_rows`: 추가한 행 지우기 · 지운 행 되살리기 · 설비군 되돌리기, 칸 수정은 저장 전 값으로 다시 저장).
- **행 추가**: [＋ 행 추가]로 표 맨 아래에 새 행(`＋`)을 만든다. 설비 호기 · 설비군 · **메모리/파운드리** · SW 버전이 필수, Line · PM · 공정 · SW 계열 · 형상 · 개조 정보는 선택(11-16). SW 계열을 비우면 아래 규칙으로 자동으로 정한다. PM이 여럿인 새 설비는 같은 호기로 줄을 더 만들고 PM마다 적는다(같은 저장 안의 새 설비에만, 이미 저장된 설비에 PM을 더하지는 않는다 — 되돌리기가 설비 전체를 지우므로). 메모리/파운드리는 비우면 저장을 막는다(11-12: 비워 두면 서버가 라인 판정값으로 몰래 정하던 것을 없앰). 칸은 현황표 기본값으로 채워 두고, 라인을 고르면 그 라인의 메모리/파운드리(`SheetRows.line_areas`: 등록값 → 설비 현황 값 → 장소표)를 알 때 그 값으로 **보이게** 바꾼다. 직접 고른 값은 라인을 바꿔도 덮어쓰지 않는다. **SW 버전은 설비군과 메모리/파운드리가 정해지면 그 계열의 최신 릴리즈 버전으로 자동으로 채운다**(`SheetRows.latest_versions`; 메모리를 가정하지 않음, 직접 고친 버전은 덮어쓰지 않음, 계열에 릴리즈가 없으면 비워 둠). 모델명은 설비군 이름으로 저장한다. 처음 보는 설비군이면 대분류 칸에서 POLY · OXIDE · KCTC 중 하나를 골라야 하고, [저장] 때 새 설비군으로 등록할지 한 번 묻는다. Site · 기준일은 현황표에서 정한다. DB 값 기준이라 원본 칸 위치는 남기지 않는다.
  - 메모리/파운드리는 적은 값 → 위치 탭에 등록한 라인 값 → 같은 현황표 같은 라인 설비 → 장소표 판정 순으로 정한다.
  - SW 계열은 같은 현황표 · 같은 설비군 · **같은 메모리/파운드리** 설비가 쓰는 계열을 따른다. 없으면 설비군(또는 상위 설비군)의 계열 중 메모리/파운드리에 맞는 것(파운드리면 '(파운드리)' 계열, UI 표기 없으면 통합UI)으로 정하고, 하나로 정할 수 없으면 거부한다. 계열이 하나도 없는 설비군이면 설비군 이름으로 계열을 만든다.
  - SW 버전이 그 계열 릴리즈 노트에 없거나, 계열에 릴리즈가 없거나, 목표 N(기준 버전)이 없으면 대시보드 · 히트맵에서 '정보 부족'으로 보인다.
- **행 삭제**: 고른 줄의 설비의 그 기준일 관측을 PM → SW → 설비 현황 순서로 지운다. 설비 호기와 가져온 원본 셀은 남긴다. 되살릴 수 있게 지운 행 전체를 MANUAL 기록 `management_delete`에 남긴다.
- **정렬**: 기본은 Line → 설비군 → 설비 호기 순(숫자는 숫자로 비교)이고, 표 위에 지금 정렬 기준을 적는다. 열 제목을 누르면 그 열 오름차순 → 내림차순 → 기본 정렬 순으로 바뀐다(제목에 ▲/▼). 정렬은 DB 값 기준이라 저장 전 수정으로는 행이 움직이지 않고, 저장한 뒤 다시 읽을 때 자리를 찾는다.
- Site · 기준일은 현황표에서 고치지 않는다(Site 이름은 위치 탭에서).
- **다른 Site 라인 안내**: [저장] 때 새 행 · 고친 Line 중 이 Site에는 없고 다른 Site에만 있는 라인(`SheetRows.elsewhere`)이 있으면 "이 현황표의 Site 설비로 저장됩니다. 그대로 저장할까요?"를 한 번 묻는다. [아니요]면 저장하지 않고 [＋ 빈 현황표]로 그 Site 현황표를 만들라고 안내한다.
- **[?] 가이드**: 설비현황 하위 탭 줄(현황표 · 설비 · 위치 · 가져온 엑셀 삭제) 오른쪽 [?]를 누르면(어느 하위 탭에서도 보임) 변경 이력 세부 정보와 같은 오른쪽 패널(`SideDrawer`)에 '새 위치에 설비 넣기' 순서가 나온다 (11-12에 3단계로 줄임: 빈 현황표(새 Site도 여기서) → 행 추가 · 값 입력(칸별 필수 · 선택 · 자동) → 저장 · 확인(새 라인 · 새 설비군도 여기서 등록)). 단계 버튼을 누르면 가이드를 닫고 그 화면이나 동작으로 간다.

### 설비군 (11-11 6차)

- **설비군 추가**: 기본형이면 같은 이름의 SW 계열을 함께 만든다(가져오기 · 릴리즈 노트에서 SW 계열을 따로 적지 않아도 되게, VOC 1). 개조형은 상위 설비군의 계열을 쓴다.
- **표에서 고치기 (11-12)**: 설비군 표의 칸을 두 번 눌러 고치고 [저장]으로 한꺼번에 반영한다(`update_groups`, 한 트랜잭션). 저장 전 칸은 노란색이고 되돌리기 · 다시 실행 아이콘(Ctrl+Z · Ctrl+Y)이 있다. 저장 전 수정이 있으면 바로 저장하는 [설비군 추가] · [삭제]는 잠긴다.
  - **대분류**(POLY · OXIDE · KCTC): 기본형만 고친다. 개조형은 상위 설비군의 대분류를 따라간다(함께 바뀜).
  - **이름**: **직접 추가한 설비군만** 바꾼다. 기본 설비군(M-C3 · M-C4 · M-C4 DFB · M-O5 Prime 등 `reference_data.MODEL_CATEGORIES`)은 번역표 · 대시보드 분류 · 내보내기가 이름으로 알아보므로 막는다(`GroupRow.builtin`). 쓰이는 설비군도 바꾸며, 그 설비군 설비 현황의 모델명과 같은 이름의 SW 계열도 함께 바꾼다.
- **삭제**: 설비 현황 · 개조형 · 릴리즈 노트 · Item 적용 모델 · 위험 지정에 쓰이지 않는 설비군만 된다. 지우면 함께 만든 빈 계열도 지운다.
- **독립 설비군으로 보기는 없앴다 (11-12 요청)**. 예전에 저장한 `independent_groups.v1` 값은 DB에 남아 있지만 화면에서 정하지도, 보이지도 않는다.

### 위치: Site · 라인 (11-11 6차)

- 트리는 **Site → Memory/Foundry → 라인**이다. 라인은 관측된 라인(설비별 최근 현황)과 등록한 라인을 합친다(`lines`). 메모리/파운드리는 등록값 → 설비 현황의 생산 영역 → 장소표(`LINE_AREAS`) 순으로 정하고, 모르면 'Memory/Foundry 모름' 아래에 둔다.
- **[＋ 라인 추가]**: Site · 메모리/파운드리 · 라인 이름을 `app_setting` `registered_lines.v1`에 저장한다. 같은 Site의 같은 라인(대소문자 무시) · 없는 Site는 거부한다.
- **[Memory/Foundry 변경]** (변경 · 지정): 등록값을 바꾸고 그 라인 설비 현황의 생산 영역도 함께 바꾼다. 모르는 라인은 어느 쪽인지 고른다. 설비 SW 계열(파운드리용 릴리즈 노트)은 바꾸지 않으므로 필요하면 현황표를 다시 가져온다.
- **표에서 고치기 (11-12)**: 바꾼 것은 모아 두었다가 [저장]으로 한 순서대로 한 트랜잭션에 반영한다(`apply_locations`). 저장 전 항목은 노란색이고 되돌리기 · 다시 실행 아이콘이 있다. 저장 전 변경이 있으면 바로 저장하는 추가 · 삭제 · [Memory/Foundry 변경]은 잠긴다. 모든 기준일의 설비 현황이 함께 바뀐다.
  - **이름 고치기**: 트리의 Site · 라인 이름을 두 번 눌러 고친다(예: P1D → P1A). 그 Site · 라인의 모든 설비 현황 · 등록값(Site는 직접 입력 현황표의 Site도)을 함께 바꾼다. 다른 Site와 같은 이름으로는 못 바꾼다(Site는 합치지 않는다).
  - **라인 합치기**: 같은 Site에 이미 있는 라인 이름을 적으면 묻고 그 라인에 합친다(예: P1D → P1F). 옮긴 설비 현황의 메모리/파운드리는 대상 라인 것을 따르고, 옛 라인 등록값은 지운다.
  - **설비 옮기기**: 오른쪽 소속 설비 표의 Line 칸에서 같은 Site의 다른 라인을 고르면 그 설비를 옮긴다. 여러 줄을 고르고 한 칸을 바꾸면 고른 설비 모두. 메모리/파운드리는 대상 라인 것을 따른다. 없는 라인으로는 옮기지 않는다(먼저 라인 추가).
  - SW 계열(파운드리용 릴리즈 노트)은 바꾸지 않는다(메모리/파운드리 변경과 같은 한계).
- **삭제**는 설비 현황이 없는 등록 Site · 라인만 된다(Site를 지우면 그 Site에 등록한 라인도).
- **판정에 바로 쓰인다**: 등록 라인은 `reference_data.default_area`가 장소표보다 먼저 본다(`use_registered_lines`, 앱 시작 · 라인 저장 때 갱신). 가져오기 · AI 분석의 메모리/파운드리 판정, 조회 라인 선택지(`database_catalog`)가 코드 수정 없이 새 라인을 쓴다.

### Site · 설비 추가 흐름 (11-11 확정)

1. 새 사업장: 위치 › [＋ Site 추가] → DB 관리 설정(`app_setting` `registered_sites.v1`)에 저장 → 대시보드·히트맵 Site 선택지와 데이터 가져오기 Site 목록에 보임 → "빈 현황표를 만들까요?" → 기준일 입력 → 빈 현황표(직접 입력) 생성. **위치 탭에 머물러** 라인을 이어서 추가할 수 있고, 현황표 탭에 가면 만든 현황표가 골라져 있다.
2. 새 라인: 현황표에 그 라인 이름을 적고 [저장]하면 메모리/파운드리를 골라 함께 등록한다. 위치 › [＋ 라인 추가]로 미리 등록해도 된다.
3. 기존 Site에 설비: 현황표에서 그 Site · 기준일 현황표를 골라 [＋ 행 추가]. 그 Site에 현황표가 없거나 새 기준일이면 현황표 탭 **[＋ 빈 현황표]**로 Site(등록 Site + 현황표가 있는 Site, 목록에 없는 이름을 적으면 새 Site로 함께 등록) · 기준일 · **메모리/파운드리(필수)**를 골라 먼저 만든다. 메모리/파운드리는 그 현황표 입력 작업에 보관해(`[현황표]` 키의 `production_area`) 새 행 · 새 라인의 기본값으로 쓴다. 위치 탭의 Site 추가 → 빈 현황표도 같은 창을 쓴다. **설비의 Site · 기준일은 행을 넣은 현황표가 정한다**(다른 Site 현황표에 넣으면 그 Site 설비가 된다).
4. 설비군 추가는 설비 탭에서도 할 수 있지만, 보통은 행 추가 때 그 자리에서 등록한다.

빈 현황표는 `import_batch`(MANUAL)의 `raw_data`에 시트 머리글과 `[현황표]` 키(Site · 기준일)를 넣어 만든다. 엑셀 시트 이름에는 `[` `]`를 쓸 수 없으므로 `[`로 시작하는 키는 시트가 아니다(`sheet_names`). 같은 Site · 기준일 현황표가 이미 있으면 만들지 않는다.

### 조회 선택지

- **설비군 추가**는 `equipment_group`에 저장한다. 조회 선택지는 `GROUP_MODELS` 이름으로 묶고, 거기에 없는 개조형은 상위 설비군에 함께 묶으며, 거기에 없는 기본형(POLY·OXIDE·KCTC, 분석 대상)은 `group-<ID>` 선택지로 같은 분류 뒤에 넣는다 (`database_source.group_keys / registered_group_options`).
- **Site**: 조회 Site 선택지는 관측된 Site에 등록 Site를 더해 만든다(설비가 없으면 칸은 `—`). 관측 Site나 이미 등록한 이름(대소문자 무시)은 거부한다.
- **라인**: 조회 라인 선택지에 등록 라인을 더한다(`extra_lines`). 라인의 메모리/파운드리는 현황의 생산 영역이 비어 있으면 판정값(`line_area`)을 써서, 라인 선택지와 설비 위치의 키가 맞는다.
- 저장 · 등록 · 삭제가 끝나면 `saved`를 보내 앱이 조회 선택지와 대시보드·히트맵을 DB에서 다시 읽고, 데이터 가져오기의 Site 목록도 다시 채운다(`after_management_save` → `configure_import_choices`).

### 가져온 엑셀 삭제 (11-11 4차)

- 화면에 들어올 때 목록을 읽어 두고, 종류 · Site · 기간(또는 계열)을 고른 뒤 '직접 선택' 오른쪽의 **[검색]**을 눌러야 그 조건의 가져온 엑셀이 2번 목록에 보인다. 조건을 바꾸면 목록을 비우고 다시 [검색]을 기다린다. 기간을 비우면 기간 제한이 없다.
- **자동 선택은 하지 않는다.** 지울 것을 체크하거나 머리 체크로 보이는 것 전체를 고른다.
- 열은 기준일 · Site · 시트 · 설비/행 · 저장일 · 저장 방식 · 상태로 나눴다(릴리즈 노트는 Site 열 숨김). '남는 기준일'은 목록에 보이는 것이 아니라 같은 종류의 저장 자료 전체에서 센다.
- 저장일은 PC 시각으로 보인다(아래 시각 표시).

### 릴리즈노트 (11-11 5차)

- **최신 버전이 위**(버전 순서 내림차순, 순서가 없는 버전은 맨 아래). 왼쪽 줄 번호는 1부터 매긴다.
- **칸 수정 · 버전/Item 추가 · 삭제 표시 · Item 순서를 모아 두었다가 [저장]으로 한꺼번에** 반영한다(노란색 저장 전 · 빨간 칸 삭제 예정). 저장 전에는 DB에 아무것도 쓰지 않는다. 삭제가 있으면 저장할 때 한 번 묻는다. 저장하지 않은 변경이 있는데 다른 계열을 고르면 저장 · 버리기 · 취소를 묻는다.
  - 저장 순서: 칸 수정(관리 저장, 검토 지문 충돌 시 거부) → 추가 · 순서 · 삭제(`apply_release`, 한 트랜잭션). 삭제 예정인 줄의 칸 수정은 저장하지 않는다.
  - 날짜 칸 · 버전 추가 · 빈 현황표 기준일은 **버전 리플레이와 같은 달력**으로 고른다(11-12, `DatePickerEdit`, 표의 Date 칸은 한 번만 눌러도 열림). Content(Item) 열이 남는 폭을 쓰고, 긴 버전 이름은 줄바꿈 없이 오른쪽을 줄인다. 버전 추가에서 날짜를 모르면 '날짜 모름'을 고른다. 적용 모델은 설비군 이름을 쉼표로, '전체'는 전체 설비(ALL)다. 틀리면 칸을 되돌리고 저장 목록에 넣지 않는다.
- **되돌리기 아이콘(Ctrl+Z)**: 저장 전에는 바로 앞 단계(칸 수정 · 추가 · 삭제 표시 · 순서) 하나씩, 저장 뒤에는 마지막 저장 전체를 되돌린다(`undo_release`: 추가한 버전 · Item 지우기, 지운 버전 · Item 되살리기, 바꾼 순서 되돌리기 + 칸 수정은 저장 전 값으로 다시 저장). 되살린 버전 · Item은 새 ID로 다시 들어가며, **삭제 때 '연결 미확인'이 된 위험 지정 연결은 되살리지 않는다**.
- **버전 추가**: 새 버전은 맨 위에 보이고, 저장하면 순서 맨 끝(기존 최대 + 10)으로 들어간다. 같은 원문인데 릴리즈 연결이 없던 설비 SW는 새 버전에 잇는다.
- **Item 추가**: 고른 줄의 버전 맨 뒤에 내용 · 적용 모델을 더한다(새 버전에도 가능). 번호(No)는 적지 않고 맨 뒤 번호 다음으로 매긴다. 적용 모델을 비우면 전체 설비(ALL).
- **Item 순서**: Item 줄을 끌어 같은 버전 안의 다른 줄에 놓으면 그 자리로 옮기고, 저장할 때 번호를 1부터 다시 매긴다. 노란색은 **옮긴 Item의 No 칸에만** 칠한다(11-12: 원래 순서를 지킨 가장 긴 줄에 들지 않은 Item. 밀려나 번호만 바뀐 Item은 칠하지 않는다). No 칸은 직접 고치지 않는다.
- **삭제**: [선택 Item 삭제]는 그 버전에서 Item 연결을 지우고, 다른 버전에 쓰이지 않는 Item이면 Item도 지운다. [선택 버전 삭제]는 버전과 그 Item 연결을 지운다. 저장 전 새 줄은 바로 없앤다. 위험 지정이 가리키던 버전 · Item은 근거를 남기고 '연결 미확인'으로 바꾸고(`StorageTransaction.delete_release_*`), 그 버전을 쓰던 설비 SW의 릴리즈 연결은 DB 규칙대로 비워진다. 그 버전으로 정한 목표 N은 다시 정해야 한다. 되살릴 수 있게 지운 버전 · Item · 연결 전체를 MANUAL 기록 `management_delete_release`에 남긴다.
- **위험 지정은 아이템 매니저에서만** 한다. 이 탭에는 위험 열·버튼이 없다. 등록한 기준의 해제·다시 사용(`is_enabled`)도 아이템 매니저 판정 팝업에서 하며, 변경 이력에는 `수정 · 위험 지정 · 사용 여부`로 남는다.

### 변경 이력 (11-11 4차)

- 기본 열(수정 일시 · 구분 · 대상 · 항목 · 수정 전 · 수정 후)만 넓게 보이고, 줄을 누르면 대시보드 설비 상세처럼 창 오른쪽에서 세부 정보 패널(`SideDrawer`)이 나온다(구분 · 전체 수정 일시 · 파일 · 시트 · 셀 · 수정 전 → 후). Esc · 접기 · 바깥 클릭이나 다른 탭으로 가면 닫힌다.
- 목록의 일시는 올해면 'MM-DD HH:MM'으로 짧게 보인다. 탭에 들어올 때마다 DB에서 다시 읽는다([새로 읽기] 버튼 없음).
- 구분: 수정(칸 · Item 순서 · 이름 · 대분류 · 라인 합치기 · 설비 라인 옮기기 · 메모리/파운드리 · 설비군 변경) · 등록(설비군 · Site · 라인 · 현황표 · 릴리즈 버전 · Item · 위험 지정) · 추가(현황표 행) · 삭제(현황표 행 · 릴리즈 버전 · 릴리즈 Item, 되돌리기로 지운 것은 '추가 취소') · 되돌리기(지운 현황표 행 · 릴리즈 줄 되살림).

### 공통

- **설명 문구 없음 (11-12 요청)**: 화면 아래 · 위의 설명 문장(현황표 · 설비 · 위치 · 릴리즈노트 · 변경 이력)과 현황표 출처 줄 · 정렬 안내, 진행 · 결과 안내 문구는 보이지 않는다. **오류 안내만** 버튼 아래에 빨간 글자로 보인다(`_Panel.say`, 마지막 안내는 `last_note`에 남긴다).
- **탭 밑줄**: 위쪽 탭(설비현황 · 릴리즈노트 · 변경 이력)의 회색 줄은 '변경 이력'에서 끝난다.
- **가져온 엑셀 삭제 기간**: 시작일 · 종료일 두 칸 대신 버전 리플레이와 같은 '시작 ~ 종료' 칸 하나(`DateRangeButton`)를 쓴다. 칸 어디를 눌러도 기간 달력이 열리고, 빠른 선택 · [직접 선택]도 이 칸에 보인다(11-12).
- **가져온 엑셀 삭제 폭**: 데이터 가져오기 화면의 스크롤 영역에서 꺼내 붙여, 화면 폭을 다 쓴다(11-12: 전에는 왼쪽 630px만 쓰고 오른쪽이 비었다).
- **열 폭**: 모든 표는 열 경계를 끌어 폭을 바꿀 수 있고, 사람이 바꾼 폭은 이 PC 설정(`QSettings`, `data_management/columns/<표>`)에 기억해 다음에도 그대로 연다. 기억한 폭이 없으면 내용 폭으로 맞춘다.
- **시각 표시**: DB의 `imported_at`은 DB 서버 시계(개발용 Docker는 UTC)로 기록되므로, 읽을 때 `SELECT NOW()`와 이 PC 시계의 차이(15분 단위)를 더해 PC 시각으로 보인다 (`clock_offset`).
- **파일 이름 보관**: 앞으로 가져오는 자료는 `import_batch.raw_data`의 `[파일]` 키(`WORKBOOK_KEY`)에 파일 이름을 함께 보관한다. 그 전에 가져온 자료는 '파일 이름 없음'으로 보인다.

## 남은 것

- 기본 설비군은 이름을 바꿀 수 없다(새 이름으로 추가). 번역표 · 조회 묶음(`GROUP_MODELS`) · 내보내기가 이름으로 이어져 있어서다.
- Site는 합치지 않는다. 다른 Site로 설비를 옮기는 기능도 없다(같은 Site 안의 라인끼리만).
- 라인의 메모리/파운드리를 바꿔도 설비 SW 계열(파운드리용 릴리즈 노트)은 그대로다.
- 새 설비군에 자동으로 만든 SW 계열은 릴리즈 노트를 가져오면 그 계열 이름과 맞춰야 한다.
- 위험 지정의 영향 버전은 시작~해제 범위만 된다(버전 목록 지정 없음).
