# 데이터 관리 화면 (11-10 개편)

사이드바 **데이터 관리** 하나로 기존 `버전 관리`·`관리 데이터` 메뉴를 대신한다. 두 화면은 다른 화면의 내부 이동(레코드 열기, Item 위험 등록 저장 등)에 계속 쓰이므로 등록은 그대로 두고 사이드바에서만 숨겼다 (`main_window.HIDDEN_MENUS`).

## 탭 구성 (고정)

| 탭 | 하위 | 하는 일 | 쓰는 기능 |
|---|---|---|---|
| 설비현황 | 현황표 | 가져온 엑셀 시트를 원래 열·행 그대로 보여 주고, DB 값과 연결된 칸을 바로 고친다 | `DataAdminService.status_sheets / sheet_grid` + 관리 저장 `gateway.save` |
| | 설비 | 설비군(기본형 + 개조형) 목록, 설비 목록, **설비군 추가** | `equipment_overview / create_group` |
| | 위치 | Site → Fab → Line 트리(저장된 관측에서 만듦), 소속 설비, **Site 추가(화면 표시용)** | `equipment_overview`, `QSettings` |

## 정한 것 (11-10)

- **수정은 바로 저장**한다. 검토대기는 없다(DB에 대기열이 없음). 저장 직전 최신 검토 지문(revision)으로 묶어 다른 곳의 변경과 충돌하면 거부된다.
- **Site 추가는 화면 표시용**이다. Site·Fab·Line 테이블이 없고 설비의 Site는 가져온 현황표로 정해진다. 추가한 Site는 이 PC 설정에만 남는다.
- **파일 이름 보관**: 앞으로 가져오는 자료는 `import_batch.raw_data`의 `[파일]` 키(`WORKBOOK_KEY`)에 파일 이름을 함께 보관한다. 엑셀 시트 이름에는 `[` `]`를 쓸 수 없어 시트와 겹치지 않는다. 시트 이름을 세는 곳(삭제 목록 `_sheet`, 재가져오기 비교)은 이 키를 뺀다. 그 전에 가져온 자료는 '파일 이름 없음'으로 보인다.
- 현황표에서 SW 버전을 고치면 릴리즈 연결(`release_version_id`)을 비워 저장 후 다시 판정한다. Site·기준일 칸은 고칠 수 없다.
- 릴리즈노트 '적용 모델'은 설비군 이름을 쉼표로 적는다(없는 이름은 저장 전에 거부).

## 남은 것

- 릴리즈노트 삭제·신규 등록은 화면에 없다(기존 서비스 미노출). 다시 가져오면 계열 전체가 교체된다.
- 위험 지정의 영향 버전은 시작~해제 범위만 된다(버전 목록 지정 없음).
- 개발용 Docker MySQL은 UTC 시각으로 저장하므로 가져온 시각·수정 일시가 9시간 이르게 보인다(기존 화면과 같음).
