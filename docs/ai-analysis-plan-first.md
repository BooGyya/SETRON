# AI 분석: AI가 계획하고 규칙이 검사·대체한다 (11/11)

## 왜 바꿨나

규칙(단어 사전)이 먼저 판단하면 말투가 늘 때마다 규칙을 더해야 하고, 규칙이 **잘못 알아들어도**("가장 마지막 데이터가 언제야?" → '언제' → 통일 예측) AI 보조가 불리지 않았다.

## 지금 구조

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 계획 | **AI** (`features/chat/classify.py` `plan`) | 직접 입력한 질문을 "어떤 도구를, 어떤 조건으로"만 JSON으로 계획 |
| 검사 | **규칙** (`recognize`, `plan` 검증) | 도구가 있는지, 이름이 선택지에 있는지, 날짜가 저장된 기준일에 있는지 |
| 계산 | **DB** (`answers.py`) | 숫자·표·그래프. 대시보드와 같은 집계 |
| 대체 | **규칙** | AI 없음·실패·형식 오류, 바로 분석 버튼·예시 카드·추천 질문, 인사말 |

도구: 조회 · 비교 · 기간 변화 · 원인 · 우선순위 · 통일 예측 · 버전 정보 · 월간 보고서 · **자료 안내**(최신 기준일, 기준일 목록, 만들 수 있는 보고서).
특별한 결과: **지원하지 않음**(주간 보고서 등) · **확인 질문**(두 가지로 읽힐 때) · **범위 밖**(날씨·잡담).

## 원칙

- AI는 답·숫자를 만들지 않는다. AI에게는 질문과 **선택지 이름 · 기준일 목록**만 보낸다 (설비 자료는 보내지 않음).
- 없는 기능·없는 날짜는 다른 것으로 바꿔 답하지 않고 "없다 + 대신 할 수 있는 것"을 말한다.
- 계획은 규칙이 읽을 수 있는 짧은 질문으로 바꿔 `recognize`에 다시 넣는다 → 조건 해석·검증은 한 곳.
- 답에 "질문을 ‘…’(으)로 이해했어요"를 남긴다 (판단 근거에 접혀 있음).

## 새 기능을 더할 때

말투 규칙이 아니라 **도구 하나**를 더한다: `TOOLS`에 이름·요청 종류·설명을 넣고, `answers.answer`에 그 요청의 답을 만든다.
잘못 알아들은 질문은 `tests/test_chat_planner.py` 같은 예시로 남겨 회귀 테스트로 쓴다.

## 범용 집계 도구 (11/11 멘토링 반영)

질문마다 도구를 만들지 않고 **무엇을 셀지 · 무엇별로 · 어떤 조건으로**를 조합한다 (`features/chat/aggregate.py`).

| 무엇을 셀지 | 계산 |
|---|---|
| 설비 수 (count) | 묶음별 설비 대수 |
| 버전 종류 수 (versions) | 같은 계열 안의 서로 다른 버전 수 |
| 파편화 (fragmentation) | 같은 계열에서 설비 두 대를 골랐을 때 버전이 다를 확률(0~1). 묶음 점수는 계열별 지수를 설비 수로 가중 평균 — **멘토 협의 전 초안**, 이 파일 한 곳에서만 정한다 |
| 목표 N 달성률 (achievement) | 저장된 목표 N · N 그룹 (대시보드와 같음) |
| 기준 버전 이상 비율 (baseline) | 질문 속 버전을 목표 자리에 넣고 대시보드와 같은 판정(`compare_version` · `summarize`) |

무엇별로: 사업장 · 라인 · 모델(설비군) · 계열 · 버전 · PM. 조건은 기존 조회 조건(사업장 · 라인 · 모델 · 계열 · 기준일) 그대로.

- 멘토 용어: 최신화율 = 목표 N 달성률, M 버전 = 기준 버전, 설비군 = 모델.
- 질문 속 기준 버전이 등록돼 있지 않으면 계산하지 않고 그 계열의 최근 버전을 안내한다.
- 저장된 목표 N을 기준 버전으로 넣은 값은 대시보드 집계와 같아야 한다 (`tests/test_chat_aggregate.py`).
- 새 묶음(예: 공정)이 생기면 `DIMENSIONS`와 `_key`에 한 줄씩 더한다.
