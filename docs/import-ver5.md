## 가져오기

- 기존 실행 중 Excel 읽기, 규칙/AI 추출, 원본 검증, 검토·편집·복원·제외, 릴리즈 교체 검토와 저장 서비스를 유지한다.
- 탭과 단계 표시는 콘텐츠 스크롤 밖에 둔다. 단계 버튼으로 각 카드 제목으로 이동한다.
- 현황표는 기준일·Site·Memory/Foundry를, 릴리즈 노트는 계열을 선택한다. 사용자가 입력한 기준은 새 추출의 빈 필드에만 채우며 원문·기존 값을 자동 덮어쓰지 않는다.
- 출처로 확인된 원본 행 번호와 추출 ID를 구분한다. 같은 원본 행이 여러 SW로 나뉘면 `12-a`, `12-b`로 표시한다. 원본 행을 모르면 미확인으로 둔다.
- 쉼표 구분자 오타는 명시적 추천 버튼으로만 수정한다. 기존 검증을 다시 거치며 버전 순서나 Item 정책을 새로 정하지 않는다.
- 편집창에서 아직 ‘수정 반영’하지 않은 입력이 있으면 저장을 막는다. 재검토는 입력을 버리거나 자동 저장하지 않는다.
- 검토 항목의 처리 칸 또는 확인 버튼으로 ‘확인 완료’를 표시할 수 있다. 이는 이 화면의 검토 표시이며 원본·IssueLevel·저장 요청의 검토 안내 개수를 바꾸지 않는다. 오류를 확인 표시로 우회할 수 없고, 초안이 바뀌면 확인 표시를 초기화한다.
- 저장 배너는 실제 SaveReceipt가 있을 때만 표시한다. 메모리 저장을 DB 저장으로 표시하지 않는다. 이동 버튼은 조회 조건을 임의 변경·적용하지 않는다.

## 직전 저장본 비교 연결 계약

`ImportPage(comparison_loader=...)` / `create_window(import_comparison_loader=...)`는 초안 사본을 받아 `ImportComparison` 또는 `None`을 반환하는 공급자를 받는다.

- 공급자가 **동일한 시트·Site 범위의 직전 저장본임을 확인**한 결과만 반환한다. UI는 전체 대시보드 자료를 해당 시트 전체로 추정하지 않는다.
- 결과: 이전 날짜·범위·버전 변경·추가·변경 없음·이번 자료에 없음·상세 설명. 대수는 0 이상의 정수다.
- 읽기는 워커에서 실행한다. 초안 변경·초기화·화면 이탈 후 이전 응답은 버린다.
- 기본 미연결·비교본 없음·읽기 실패에는 대수를 0으로 꾸미지 않고 안내를 표시한다.
- ‘이번 자료에 없음’은 비교 정보일 뿐, 과거 자료 자동 삭제를 의미하지 않는다.

## 저장된 데이터 삭제 연결 계약

`ImportPage(delete_gateway=...)` / `create_window(import_delete_gateway=...)`는 다음 서비스를 선택적으로 받는다. 기본 앱에는 삭제 서비스를 자동 생성하지 않으며 UI에서 SQL을 실행하지 않는다.

1. `list_batches() -> DeletionCatalog`: revision, 저장 묶음의 불변 key, 종류, 날짜 또는 계열, Site, 시트, 물리 설비 수, 실제 저장 행 수, 저장 시각·방식.
2. `delete(DeletionPlan) -> DeletionResult`: **서비스가 revision·key·종류·기간·Site/계열과 삭제 영향을 재검증**한 뒤 전부 삭제하거나 전부 유지한다. 릴리즈 삭제의 Item·목표 N·위험 근거 처리는 UI가 결정하지 않는다.
3. `success`: 요청 key 전체의 확정 삭제와 새 revision. `failed`: 변경 없음이 확정된 실패. `unknown` 또는 예외·불완전 응답: 결과 미확인으로 잠그고 중복 요청 금지.

- 날짜 범위는 양끝을 포함한다. 물리 대수와 SW/저장 행 수를 혼동하지 않는다.
- 머리글 전체 선택은 현재 기간·Site·계열에 맞는 묶음만 선택한다. 선택 해제·부분 선택을 구분하며 취소하면 원래 가져오기 탭으로 돌아간다.
- 다른 Site·시트의 자료가 남는 기준일은 ‘남는 기준일’에 포함한다.
- 릴리즈 노트는 기간/Site 필터를 쓰지 않고 명시된 계열을 선택한다.
- 확인창은 정확한 ‘삭제’ 입력과 클릭을 요구한다. 확인 중 선택이나 목록 revision이 바뀌면 요청을 거부한다.
- 미연결 시 빈 목록과 안내를 표시하며 실제 삭제를 실행할 수 없다. 확인창 자체도 연결 없이 실행 승인되지 않는다.
- DB 내보내기 버튼은 기존 SQL 내보내기 공급자가 있을 때만 활성화한다.
- 확정 삭제 후에만 기존 조회·AI·Item 결과를 무효화한다. 삭제 중에는 앱 종료를 막는다.
