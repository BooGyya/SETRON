## 가져오기

- 기존 실행 중 Excel 읽기, 규칙/AI 추출, 원본 검증, 검토·편집·복원·제외, 릴리즈 교체 검토와 저장 서비스를 유지한다.
- 탭과 단계 표시는 콘텐츠 스크롤 밖에 둔다. 단계 버튼으로 각 카드 제목으로 이동한다.
- 현황표는 기준일·Site·Memory/Foundry를, 릴리즈 노트는 계열을 선택한다. 사용자가 입력한 기준은 새 추출의 빈 필드에만 채우며 원문·기존 값을 자동 덮어쓰지 않는다.
- 출처로 확인된 원본 행 번호와 추출 ID를 구분한다. 같은 원본 행이 여러 SW로 나뉘면 `12-a`, `12-b`로 표시한다. 원본 행을 모르면 미확인으로 둔다.
- 쉼표 구분자 오타는 명시적 추천 버튼으로만 수정한다. 기존 검증을 다시 거치며 버전 순서나 Item 정책을 새로 정하지 않는다.
- 값은 추출 표의 칸을 더블클릭(또는 F2)해 바로 고친다. 행마다 열리던 값 수정 칸과 ‘수정 반영’ 버튼은 없앴다 (11-10 2차 5-3). 고친 칸은 노란 배경, 오류 칸은 빨간 글자·테두리로 표시하고, 원래 값·오류 설명·원본 셀 주소는 칸에 마우스를 올리면 보인다. ‘선택 행 되돌리기’·‘선택 행 제외’는 표 위에서 고른 행에 적용한다.
- 자동으로 비어 있던 칸의 오류는 그 칸을 직접 열어 빈 채로 확정해야 풀린다. 다른 칸을 고친 것만으로는 풀리지 않는다.
- 원본 셀을 확인할 수 없는 행은 ‘출처 셀’ 칸을 더블클릭해 원본에서 확인한 셀을 지정한다.
- 검토 항목의 처리 칸 또는 확인 버튼으로 ‘확인 완료’를 표시할 수 있다. 이는 이 화면의 검토 표시이며 원본·IssueLevel·저장 요청의 검토 안내 개수를 바꾸지 않는다. 오류를 확인 표시로 우회할 수 없고, 초안이 바뀌면 확인 표시를 초기화한다.
- 저장을 마치면 창 위쪽에 토스트로 알리고 1단계로 돌아간다. 고른 통합문서는 남기고 시트 선택·미리보기·검토 내용·공통 기준은 비운다. 저장 버튼 아래 결과 문구는 두지 않는다 (11-10 2차 1-1·1-2). 메모리 저장은 토스트에 ‘메모리 저장(DB 미연결)’로 구분한다. 목표 N 재확인·수동 위험 미확인 같은 저장 뒤 확인할 점도 토스트로 알린다.
- 단계 띠 오른쪽의 상태 배지는 없앴다 (11-10 2차 2-2). 오류·실패는 토스트로 띄운다.
- 직전 저장본 비교 상자는 비교 결과가 있을 때만 보인다 (11-10 2차 1-3).

- 통합문서 목록·시트 읽기·추출·기존 자료 검토·직전 저장본 비교·저장·삭제 목록/삭제에 작업명과 무한 진행 막대가 있는 팝업을 표시한다. 제공되지 않는 진행률이나 완료 시간을 만들지 않는다.

- Excel 목록/시트 읽기와 저장 호출은 워커에서 실행한다. 실제 Excel COM은 그 워커에서 초기화·정리하고 GUI에는 값·셀 위치만 돌려준다. `load_workbooks()`의 True는 조회 요청 수락이며 조회 성공/파일 존재를 뜻하지 않는다.
- 저장 중에는 초안 초기화·중복 저장·종료를 막는다. 저장 결과 미확인 상태에서는 목록을 다시 읽어도 잠금이 풀리지 않는다.
- Figma `1981:8041` 팝업의 흰 카드·16px 라운드·28/24px 여백을 가져오기 확인/선택 창에 적용한다. 저장·번역표 적용·매칭·수정값 충돌·위험 보존/재연결의 기존 선택 의미는 바꾸지 않으며 취소/기존의 안전한 선택을 기본으로 둔다. 긴 확인 근거는 스크롤한다.

## 직전 저장본 비교 연결 계약

DB에 연결하면 검토가 끝난 설비 현황표를 같은 사업장·시트에서 저장한 직전 기준일의 Excel 자료와 비교한다. 같은 날과 미래 자료는 제외한다. 제외 행을 뺀 초안에서 PM·SW 계열·버전 구성을 비교하고, 한 호기는 한 대로 센다.

`ImportPage(comparison_loader=...)` / `create_window(import_comparison_loader=...)`는 초안 사본을 받아 `ImportComparison` 또는 `None`을 반환하는 공급자를 받는다.

- 공급자가 **동일한 시트·Site 범위의 직전 저장본임을 확인**한 결과만 반환한다. UI는 전체 대시보드 자료를 해당 시트 전체로 추정하지 않는다.
- 결과: 이전 날짜·범위·버전 변경·추가·변경 없음·이번 자료에 없음·상세 설명. 대수는 0 이상의 정수다.
- 읽기는 워커에서 실행한다. 초안 변경·초기화·화면 이탈 후 이전 응답은 버린다.
- 기본 미연결·비교본 없음·읽기 실패에는 대수를 0으로 꾸미지 않고 안내를 표시한다.
- ‘이번 자료에 없음’은 비교 정보일 뿐, 과거 자료 자동 삭제를 의미하지 않는다.

## 저장된 데이터 삭제 연결 계약

`ImportPage(delete_gateway=...)` / `create_window(import_delete_gateway=...)`는 다음 서비스를 선택적으로 받는다. 기본 앱에는 삭제 서비스를 자동 생성하지 않으며 UI에서 SQL을 실행하지 않는다.

1. `list_batches() -> DeletionCatalog`: revision, 저장 묶음의 불변 key, 종류, 날짜 또는 계열, Site, 시트, 물리 설비 수, 실제 저장 행 수, 저장 시각·방식.
2. `delete(DeletionPlan) -> DeletionResult`: **서비스가 revision·key·종류·기간·Site/계열과 삭제 영향을 재검증**한 뒤 전부 삭제하거나 전부 유지한다. 릴리즈 삭제의 Item·목표 N·위험 근거 처리는 UI가 결정하지 않는다.
3. `success`: 요청 key 전체의 확정 삭제와 새 revision. `failed`: 변경 없음이 확정된 실패. `unknown` 또는 예외·불완전 응답: 결과 미확인으로 잠그고 중복 요청 금지.

- 날짜 범위는 양끝을 포함한다. 물리 대수와 SW/저장 행 수를 혼동하지 않는다.
- 머리글 전체 선택은 현재 기간·Site·계열에 맞는 묶음만 선택한다. 선택 해제·부분 선택을 구분하며 취소하면 원래 가져오기 탭으로 돌아간다.
- 다른 Site·시트의 자료가 남는 기준일은 ‘남는 기준일’에 포함한다.
- 릴리즈 노트는 기간/Site 필터를 쓰지 않고 명시된 계열을 선택한다.
- 확인창은 정확한 ‘삭제’ 입력과 클릭을 요구한다. 확인 중 선택이나 목록 revision이 바뀌면 요청을 거부한다.
- 미연결 시 빈 목록과 안내를 표시하며 실제 삭제를 실행할 수 없다. 확인창 자체도 연결 없이 실행 승인되지 않는다.
- DB 내보내기 버튼은 기존 SQL 내보내기 공급자가 있을 때만 활성화한다.
- 확정 삭제 후에만 기존 조회·AI·Item 결과를 무효화한다. 삭제 중에는 앱 종료를 막는다.

## 삭제 화면의 배치·날짜 입력

- Figma `1981:7563`의 필터 카드와 `1981:7600`의 빠른 선택을 기준으로 한다. 보이는 입력칸만 왼쪽부터 16px 간격으로 배치하고, 자료 종류가 바뀌면 숨긴 Site·날짜 칸의 빈 자리를 남기지 않는다. 좁은 창은 2열/1열로 바뀐다.
- ‘빠른 선택’ 라벨 옆에는 가장 최근 기준일·최근 1개월·최근 3개월·직접 선택의 32px 둥근 칩을 둔다. 기존 기간 선택 동작은 유지한다. ‘저장된 자료 조회’는 칩과 별도의 행 오른쪽 끝에 둔다.
- 릴리즈 안내는 릴리즈 노트 선택 시에만 보인다. 날짜/기간 안내도 같은 회색을 사용한다. 자료 종류에 맞춰 2단계 제목을 ‘삭제될 기준일’/‘삭제될 릴리즈 묶음’으로 표시한다.
- 날짜 입력은 Qt의 `0000-00-00` 마스크로 숫자 8자리·하이픈 형식을 유지한다. 문자와 초과 숫자는 입력하지 못하며 붙여넣기·되돌리기·달력은 네이티브 동작을 유지한다. 빈 마스크의 구분자는 실제 값으로 취급하지 않는다. 존재하지 않는 날짜·미완성 날짜·역전된 기간은 삭제 대상을 만들 수 없다.
- 삭제 시작일·종료일과 가져오기의 공통 기준일은 텍스트 영역을 클릭한 위치와 관계없이 첫 자리부터 입력한다. 클릭만으로 기존 값을 지우지 않고, 검은 입력 마스크 블록 커서만 표시하지 않는다. 포커스 테두리·실제 텍스트 선택·키보드 이동·붙여넣기·되돌리기·달력은 유지한다. 다른 입력칸은 변경하지 않는다. Site는 시트에 누락된 사업장을 보완할 수 있도록 목록 선택·직접 입력을 유지하며, 입력만으로 검토 중인 행이나 DB를 변경하지 않는다.
- Figma `1981:7732`의 세 지표 묶음과 `1981:7747`의 노란 백업 안내/오른쪽 DB 내보내기를 적용한다. 미연결 대수는 ‘—’로 유지하고 릴리즈에는 날짜 잔여 지표를 표시하지 않는다. 원본/DB 삭제 서비스나 삭제 정책은 변경하지 않는다.

## 검증

### 삭제 화면 전용 단계 탭

‘저장된 데이터 삭제’ 탭에는 ‘1 삭제 범위 선택 / 2 삭제 대상 확인 / 3 삭제 영향 확인’을 스크롤 영역 위에 고정한다. 클릭·키보드 선택은 해당 카드로 이동하고 현재 탭만 강조한다. 실제 조회·자료 선택·삭제 요청을 실행하거나 이전 단계를 완료로 표시하지 않는다. ‘가져오기’로 돌아가면 기존 4단계와 편집 중인 초안을 유지한다.

삭제 화면 상단의 서비스 미연결 안내 문구와 빈 안내 공간은 제거한다. 조회 전에는 ‘저장된 자료를 조회해 주세요.’를 표시하며, 목록 미확인은 빈 DB나 0건으로 취급하지 않는다. 삭제 잠금·명시적 확인 및 실제 실패/결과 미확인 경고는 유지한다.
