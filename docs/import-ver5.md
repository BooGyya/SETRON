## Excel 탭

단계 카드: **1. Excel 통합문서 · 시트 선택** → **2. 원본 미리보기** → **3. AI 추출 결과 검토 · 수정** → **4. 변경분 확인 · 저장**. 위쪽 단계 띠(1~4)는 스크롤 밖에 고정하고, 누르면 그 카드로 이동한다.

| 단계 | 화면 글자 |
| --- | --- |
| 1 | 통합문서 · 시트 · 가져올 자료 종류 선택, [열린 통합문서 불러오기], [시트 읽기], [↺](가져오기 초기화) |
| 2 | 원본 미리보기 표(범위 · 병합 정보) |
| 3 | [AI 추출], `기준 날짜 · Site` 상자(기준일 · Site · Memory/Foundry, [모든 행에 적용], `이미 있는 값도 덮어쓰기`), 추출 표, [선택 행 되돌리기] · [선택 행 제외], [빈칸 자동 채우기], `검토 항목` · [선택 항목 확인 완료] |
| 4 | 저장 요약, 직전 저장본 비교(결과가 있을 때만), [검토 완료 · 저장] · [다시 검사] · [대시보드로 이동] |

- 기존 실행 중 Excel 읽기, 규칙/AI 추출, 원본 검증, 검토 · 편집 · 복원 · 제외, 릴리즈 교체 검토와 저장 서비스를 쓴다.
- `기준 날짜 · Site` 상자는 현황표일 때만 보인다. Memory/Foundry는 `Memory/Foundry · 라인 기준 자동` / `Memory` / `Foundry`. [모든 행에 적용]은 빈 칸에만 채우고, `이미 있는 값도 덮어쓰기`를 체크하면 기존 값도 바꾼다. Site는 목록 선택 · 직접 입력이 모두 된다.
- 릴리즈 노트의 설비군/SW 계열 입력 칸은 화면에서 뺐다. 계열은 추출 결과에서 확인한다.
- 출처로 확인된 원본 행 번호와 추출 ID를 구분한다. 같은 원본 행이 여러 SW로 나뉘면 `12-a`, `12-b`로 표시한다. 원본 행을 모르면 미확인으로 둔다.
- 값은 추출 표의 칸을 더블클릭(또는 F2)해 바로 고친다 (11-10 2차 5-3). 고친 칸은 노란 배경, 오류 칸은 빨간 글자 · 테두리. 원래 값 · 오류 설명 · 원본 셀 주소는 칸에 마우스를 올리면 보인다.
- 자동으로 비어 있던 칸의 오류는 그 칸을 직접 열어 빈 채로 확정해야 풀린다.
- 원본 셀을 확인할 수 없는 행은 ‘출처 셀’ 칸을 더블클릭해 원본에서 확인한 셀을 지정한다.
- [선택 항목 확인 완료]는 이 화면의 검토 표시다. 원본 · IssueLevel · 저장 요청의 검토 안내 개수를 바꾸지 않는다. 오류를 확인 표시로 우회할 수 없고, 초안이 바뀌면 확인 표시를 초기화한다.
- 저장을 마치면 창 위쪽 토스트로 알리고 1단계로 돌아간다 (11-10 2차 1-1 · 1-2). 고른 통합문서는 남기고 시트 선택 · 미리보기 · 검토 내용 · 공통 기준은 비운다. DB 미연결 메모리 저장은 토스트에서 구분한다. 목표 N 재확인 · 수동 위험 미확인 같은 저장 뒤 확인할 점도 토스트로 알린다.
- 단계 띠 오른쪽 상태 배지는 없다 (11-10 2차 2-2). 오류 · 실패는 토스트로 띄운다.

### 진행 표시 · 확인 팝업

- 단계 번호 1~4는 완료 후에도 유지한다. 끝난 단계(초록) · 지금 단계(파랑) · 남은 단계(회색)를 색으로만 구분하고 ‘완료’ 글자는 두지 않는다 (11-10 2차 2-1).
- [↺]는 통합문서/시트 선택 · 미리보기 · 추출 결과 · 미저장 편집 · 공통 기준을 비우고 1단계로 돌아간다. 작업 내용이 있으면 ‘취소 / 확인’ 창을 먼저 띄우고 취소를 기본으로 둔다. 원본 Excel · 저장된 데이터는 바꾸지 않는다. 읽기 · 추출 · 검토 · 비교 · 저장 중이거나 저장 결과 미확인이면 초기화를 막는다.
- [AI 추출]: 정해진 양식은 규칙으로 먼저 읽고, 안 되면 AI를 쓴다. 버튼 옆에는 ‘AI 추출 전 → 추출 중 → 추출 완료’만 표시하고, 규칙(RULE) · 실제 AI(REAL) · 예제(EXAMPLE) 출처는 마우스를 올리면 보인다 (11-10 2차 5-1 · 5-2). 예제 응답은 노란색으로 구분한다.
- 통합문서 목록 · 시트 읽기 · 추출 · 기존 자료 검토 · 직전 저장본 비교 · 저장에 작업명과 무한 진행 막대가 있는 팝업을 띄운다(예: `열린 통합문서 확인 중`, `시트 읽는 중`, `변경분 저장 중`). 없는 진행률이나 완료 시간을 만들지 않는다. 완료 · 실패 시 자동으로 닫힌다.
- Excel 목록/시트 읽기와 저장은 워커에서 실행한다. Excel COM은 그 워커에서 초기화 · 정리하고 GUI에는 값 · 셀 위치만 돌려준다.
- 저장 중에는 초안 초기화 · 중복 저장 · 종료를 막는다. 저장 결과 미확인 상태에서는 목록을 다시 읽어도 잠금이 풀리지 않는다.
- 확인/선택 창(Figma `1981:8041`)은 흰 카드 · 16px 라운드. 저장 · 번역표 적용 · 매칭 · 수정값 충돌 · 위험 보존/재연결의 선택 의미는 바꾸지 않으며 취소/안전한 선택을 기본으로 둔다.

### 직전 저장본 비교 연결 계약

DB에 연결하면 검토가 끝난 설비 현황표를 같은 사업장 · 시트에서 저장한 직전 기준일의 Excel 자료와 비교한다. 같은 날과 미래 자료는 제외한다. 제외 행을 뺀 초안에서 PM · SW 계열 · 버전 구성을 비교하고, 한 호기는 한 대로 센다.

`ImportPage(comparison_loader=...)` / `create_window(import_comparison_loader=...)`는 초안 사본을 받아 `ImportComparison` 또는 `None`을 반환하는 공급자를 받는다.

- 공급자가 **동일한 시트 · Site 범위의 직전 저장본임을 확인**한 결과만 반환한다.
- 결과: 이전 날짜 · 범위 · 버전 변경 · 추가 · 변경 없음 · 이번 자료에 없음 · 상세 설명. 대수는 0 이상의 정수다.
- 읽기는 워커에서 실행한다. 초안 변경 · 초기화 · 화면 이탈 후 이전 응답은 버린다.
- 미연결 · 비교본 없음 · 읽기 실패에는 대수를 0으로 꾸미지 않는다.
- ‘이번 자료에 없음’은 비교 정보일 뿐 과거 자료 자동 삭제를 뜻하지 않는다.

## SQL 탭

카드 제목 **SQL 데이터 가져오기**. 안내: SETRON의 ‘DB 전체 SQL’에서 내보낸 `.sql` 파일을 선택하고 대상 DB에 반영할 변경 사항을 검토한다.

| 화면 | 내용 |
| --- | --- |
| 가져오기 방식 | **신규 항목만 추가** / **같은 항목 덮어쓰기** |
| 상태 배지 | `파일 선택 대기` → `검토 대기` → `비교 중` → `검토 완료`(또는 `가져올 변경분 없음` · `검토 실패`) → `가져오기 중`/`병합 중` → `가져오기 완료`(또는 `가져오기 실패` · `가져오기 결과 확인 필요`). DB 연결이 없으면 `DB 연결 필요` |
| 버튼 | [SQL 파일 선택] · [변경 사항 검토] · [가져오기] |

- [SQL 파일 선택]으로 `.sql` 파일을 고르면 경로가 보인다. 파일이나 방식을 바꾸면 검토 결과를 버린다.
- [변경 사항 검토]는 워커에서 파일을 읽고 대상 DB와 비교해 요약을 보인다(`features/db_import/service.py` `preview`). 원본 DB의 내부 ID는 대상 DB의 업무 키와 참조 관계에 맞춰 바꾼다(`merge.py`).
- [가져오기]는 변경분이 있을 때만 켜진다. 확인 창(`SQL 데이터 가져오기 확인`, 대상 DB에 자료가 있으면 `SQL 데이터 병합 확인`)에 파일 이름 · 방식 · 요약을 보이고, 확인해야 저장한다.
- 저장은 한 트랜잭션이다. 검토 뒤 대상 DB 설정이나 내용이 바뀌었으면 거부하고 다시 검토하게 한다(`대상 DB가 미리보기 이후 바뀌었습니다. …`). 커밋 결과를 알 수 없으면 `가져오기 결과 확인 필요`로 남긴다.
- 완료 뒤 데이터 관리 화면은 다음에 볼 때 DB에서 다시 읽는다.

## 저장된 데이터 삭제 연결 계약

삭제 화면(`ui/import_delete.py` `ImportDeletePage`)은 지금 데이터 관리 › 가져온 엑셀 삭제에서 보인다. 서비스 계약은 그대로다.

`ImportPage(delete_gateway=...)` / `create_window(import_delete_gateway=...)`는 다음 서비스를 선택적으로 받는다. UI에서 SQL을 실행하지 않는다.

1. `list_batches() -> DeletionCatalog`: revision, 저장 묶음의 불변 key, 종류, 날짜 또는 계열, Site, 시트, 물리 설비 수, 실제 저장 행 수, 저장 시각 · 방식.
2. `delete(DeletionPlan) -> DeletionResult`: **서비스가 revision · key · 종류 · 기간 · Site/계열과 삭제 영향을 재검증**한 뒤 전부 삭제하거나 전부 유지한다.
3. `success`: 요청 key 전체의 확정 삭제와 새 revision. `failed`: 변경 없음이 확정된 실패. `unknown` 또는 예외 · 불완전 응답: 결과 미확인으로 잠그고 중복 요청 금지.

- 화면: `1. 삭제할 자료와 기간 선택`(자료 종류 · Site · 기간 또는 설비군/계열, 빠른 선택 `가장 최근 기준일` · `최근 1개월` · `최근 3개월` · `직접 선택`, **[검색]**) → `2. 지울 엑셀 선택` → `3. 삭제 영향 확인`(삭제할 기준일 · 삭제할 현황표 행 · 남는 기준일, 백업 안내와 [DB 내보내기]) → [취소] · [선택한 자료 삭제].
- 예전 `저장된 자료 조회` 버튼은 숨겼다. 조건을 고르고 [검색]을 눌러야 목록이 보인다.
- 확인 창(`저장된 데이터 삭제 확인`)은 실제 선택 목록을 다시 보이고, 칸에 정확히 `삭제`를 입력해야 [삭제]가 된다. 확인 중 선택이나 목록 revision이 바뀌면 거부한다.
- 확정 삭제 뒤에만 기존 조회 · AI · Item 결과를 무효화한다. 삭제 중에는 앱 종료를 막는다.

## 날짜 입력

가져오기 기준일과 데이터 관리의 날짜 칸은 대시보드와 같은 `DateRangeDialog`의 단일 날짜 모드를 쓴다(연도→월 선택, 취소/적용). 날짜를 고른 뒤 적용해야 입력값이 바뀌며, 취소 · Esc · 창 밖 클릭은 기존 값을 유지한다. 가져온 엑셀 삭제 기간과 리플레이 · 보고서의 기간은 같은 팝업의 기간 모드를 쓴다.

기준일 칸은 클릭 위치와 관계없이 첫 자리부터 입력한다. Qt `0000-00-00` 마스크로 숫자 8자리 · 하이픈 형식을 지키며, 존재하지 않는 날짜 · 미완성 날짜는 적용되지 않는다.
