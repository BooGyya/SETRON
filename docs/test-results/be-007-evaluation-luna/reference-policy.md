# BE-007 전체 필드 평가 기준

이 평가는 화성 교육용 설비 현황표의 Memory·Foundry 두 시트를 대상으로 한다. 정답은 AI 재호출 전에 `source-snapshot.json`의 셀 값·병합 범위에서 만든다. AI 응답이나 제품의 정규화 함수를 정답 생성에 사용하지 않는다.

사용자가 확인한 기준은 **원본 셀 기준으로 평가하고 확정된 정규화 규칙만 적용**하는 것이다. 파일명에서 사업장을, 시트명에서 Memory·Foundry를 채우지 않는다.

## 평가 단계

- `raw`: AI가 반환한 필드의 원문 표기와 원본 기반 추출 정답을 비교한다. 셀에 없는 값은 `null`이다. 후처리에서 만들도록 분리한 계열명 등은 원문 단계에서 임의로 채우지 않는다. 이 지표는 원문 추출 계약의 엄격한 일치율이다.
- `normalized`: 제품의 실제 검토 자료를 독립적으로 작성한 정규화 정답과 비교한다. 값이 확정되지 않는 필드는 `unresolved`로 표시하고 값 일치율 분모에서 제외한다. 제외 건수·평가 커버리지와 반환값을 별도로 공개한다.

전체 16개 필드를 빠짐없이 정답표에 넣는다. 필드별 일치율, 전체 평가 가능 필드의 일치율, 비어 있지 않은 정답의 일치율, 원본 누락에 대한 추가 생성, 레코드 누락·추가를 함께 측정한다. `null`이 많은 입력에서 전체 일치율만으로 품질을 판단하지 않는다.

## 필드별 원본 규칙

| 필드 | 정답의 근거와 규칙 |
| --- | --- |
| base_date | 두 시트의 데이터 영역에 기준일 셀이 없으므로 `null`. 파일 수정일 등으로 채우지 않음 |
| site | Line 셀에 `(기흥)`처럼 명시된 사업장만 분리. `MR2동`, `V1` 등의 건물·라인 표기에서 도시를 추정하지 않음 |
| line | 실제 병합 범위의 앵커 값만 공유. 사업장 괄호는 분리하고 나머지 라인 원문은 유지. 병합되지 않은 공란을 앞 행으로 채우지 않음 |
| group_name | 원문 단계는 A열의 실제 병합 앵커 값. 정규화는 POLY·OXIDE·KCTC·HPA. 명시값과 확인된 모델 소속이 충돌하면 판정 보류 |
| model_name | 모델 셀에서 UI·형상·CIP 표기를 분리. Prime은 별도 모델로 유지. `M-O2/O3` 혼합형은 명시된 PM 설명에 따라 분리 |
| production_area | 데이터 셀에 Memory·Foundry 값이 없으므로 `null`. 시트명을 값으로 사용하지 않음 |
| equipment_code | 호기 셀의 문자열 그대로. Memory E열, Foundry D열 |
| pm_name | 명시된 PM 설명이 있는 혼합형만 분리. 원문 단계는 `PM1`, `2`, `PM3`, `4`; 정규화 단계는 PM1~PM4 |
| family_name | 별도 계열 셀이 없어 원문 단계는 `null`. 정규화 단계는 확정된 C3 공유 규칙만 C3로 지정. 다른 모델의 DB 계열은 이 파일만으로 확정하지 않아 판정 보류 |
| version_raw | SW 열의 원문. 혼합형은 해당 모델에 라벨로 연결된 전체 버전만 분리. 공란과 `메모리버전임` 같은 메모도 그대로 기록하며 버전을 생성하지 않음 |
| ui_type | 모델 셀의 구UI·통합UI·Smart UI 원문. 구UI·통합UI만 LEGACY·INTEGRATED로 정규화. Smart UI의 정규화 대응은 미확정이므로 판정 보류 |
| structure_type | 모델 셀의 Inline·Cluster 원문. 정규화 시 INLINE·CLUSTER |
| geometry_type | 모델 셀에 명시된 5각·6각만 사용 |
| modification_type | 모델 셀에 명시된 CIP·Prime 표기를 보존. 비어 있는 개조 현황 열에서 적용 여부를 만들지 않음 |
| engine_version | Engine 열의 값만 사용. SW 값으로 대체하지 않음 |
| epd_version | EPD Version 열의 값만 사용. SW 값으로 대체하지 않음 |

모델명 정규화는 M5→M-O5, 명시적인 공유 접두사 M-O2/O3의 복원, 별도 모델인 M-O5 Prime 표기만 적용한다. 다른 별칭이나 릴리즈 대응은 추정하지 않는다. 정답 생성기는 확인하지 못한 모델 표기를 만나면 실패하게 하여 조용히 일반화하지 않는다.

## 채점과 정렬

레코드는 원본 호기 셀 주소와 PM 위치로 정렬한다. AI가 출처를 누락하면 같은 시트 안에서 유일하게 식별되는 호기 값으로만 보조 정렬하고 그 방법을 기록한다. 출처의 정확성은 값 일치와 별도로 기록한다. 중복 결과는 처음 행만 대응시키고 나머지는 추가 레코드로 계산한다.

- 누락 레코드는 정답이 `null`인 필드까지 실패로 계산한다. 응답이 없는 것을 올바른 `null` 반환으로 세지 않는다.
- 추가 레코드는 16개 필드 모두 추가 오류로 분모에 포함한다.
- `unresolved`는 값 일치율 분모에서 제외하되 보류 필드에 반환된 값도 모두 대조표에 보존한다.
- 비어 있지 않은 정답 지표는 원본에 실제 값이 있는 평가 가능 필드만 분모로 사용한다.
- 전체 일치율은 평가 가능한 필드의 단순 합산 비율이다. 모델·시트·업무 중요도별 가중치는 적용하지 않는다.
- 일치율은 이 파일의 추출 계약에 대한 규칙 기반 평가이며 모든 업무 정답에 대한 전문가 인증이나 다른 양식에 대한 일반화 정확도가 아니다.

원본 스냅샷·정답표·정책의 해시는 요청 전에 기록한다. 두 호출이 끝난 뒤 AI 응답에 맞춰 정답값을 수정하지 않는다. 평가 구현 오류를 고치는 경우에는 정답 해시와 코드 변경을 구분해 기록한다.
