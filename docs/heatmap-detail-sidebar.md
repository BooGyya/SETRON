# 히트맵 설비 상세 사이드 패널

## 설계와 구현 범위

Figma `자율PJT_세메스` → `VER5 - 황민정` → **2-1. 버전 히트맵 · 설비 상세 (타일 클릭 → 사이드 패널)** 기준이다.
대표 혼합 SW 화면은 [1391:18748](https://www.figma.com/design/CCtz444SPLckGcKKuYgUi3?node-id=1391-18748), 패널은 `1391:18957`이다.
목표 달성·미달·위험 후보·정보 부족·HPA 제외 상태의 대표 패널도 확인했다.

- 타일 클릭/키보드 선택 시 라우트를 바꾸지 않고 캔버스 오른쪽에 560px 패널을 연다. 낮은 창에서는 패널 안에서만 스크롤한다.
- 설비 호기·원본 모델, 위험 상태, 위치, 실제 관측일, 설비 전체 목표 판정, 현재/목표 버전, 비교 근거, 설치 PM, 관측 출처를 표시한다.
- 위험 후보 설비는 정보 카드 아래 `위험 판정 이유` 카드에 판정 기준 분류(적용 위험: 결함 Item·위험 버전 사용 / 미적용 위험: 필수 Item 미적용)별 기준명·PM·버전·판정 문구를 보인다. 근거가 연결되지 않으면 `세부 근거 미연결`로 두고, 미확인 근거는 `미확인` 묶음으로 따로 보인다. 대시보드 설비 목록 패널의 상세도 같은 카드를 쓴다.
- 동일 모델·계열·버전·목표·판정·근거인 PM만 같은 SW 카드로 묶는다. 선택 설비군 밖의 SW도 해당 설비의 전체 상세에 표시하되 조회 범위/KPI는 넓히지 않는다.
- SW 카드 및 `판정 · 원본 근거`를 접고 펼칠 수 있다. 다른 설비 선택 시 펼침 상태와 패널 스크롤을 초기화한다.
- 두 영역의 오른쪽 화살표는 펼친 상태에서 위쪽, 접힌 상태에서 아래쪽을 가리킨다. 화살표는 접어도 사라지지 않으며 근거 영역의 펼치기/접기 글자는 표시하지 않는다.
- 닫기·Esc·배경 클릭은 패널만 닫고 선택 타일로 키보드 초점을 돌린다. Tab 초점은 열린 패널 안에서 순환한다.
- 새 조회·조회 실패·선택지 무효화·다른 메뉴 이동·관리 저장에 따른 자료 무효화 시 패널과 편집 위치 조회를 닫는다. 조건 초안만 편집할 때는 적용된 결과를 유지한다.
- 대시보드/설비 목록에서 여는 기존 전체 상세와 Item 근거 상세는 변경하지 않는다.

## 데이터/편집 경계

기존 `EquipmentPage`와 동일한 전체 관측·PM 비교 결과를 사용한다. Figma의 예제 호기, 버전, 위험 사유, 문서/셀 주소를 실제 데이터처럼 복사하지 않는다.
목표 미달을 위험 후보로 추론하지 않으며, 목표 달성이 위험 해제를 뜻하지 않는다. HPA는 분석 제외이지 안전 확정이 아니다.
규칙·필수 Item명·릴리즈 문서/원본 위치는 기존 상세 공급자가 미연결로 반환하면 그대로 표시한다.

`버전 정보 수정`은 연결된 DB에서 **설비 ID + 실제 관측일**의 SW/PM 기본키를 백그라운드로 확인한다.
PM이 여러 개면 사용자가 수정할 PM을 고른다. 공유 SW는 공유 부모 행 대신 PM별 편집으로 연결한다.
기존 관리 화면의 원본 보존·변경 검토·명시적 저장 절차를 사용하며 패널에서 자동 저장하지 않는다.
DB 관리 연결이 없거나 SW 관측이 없는 경우 수정 버튼은 비활성화된다. 읽기 실패는 패널 안에서 재시도할 수 있다.

## 수동 확인 순서

1. 앱 실행 → 조회 적용 → 버전 히트맵 → 타일 클릭. 좌측 히트맵 메뉴와 뒤쪽 타일이 그대로인지 확인한다.
2. SW 카드의 현재 버전/목표 N/PM, `판정 · 원본 근거`의 실제 관측일/출처를 확인한다.
3. 닫기·Esc·배경 클릭을 각각 확인하고, 원래 타일 선택·보기 방식·스크롤이 유지되는지 확인한다.
4. 다른 설비를 선택한 뒤 새로 조회하여 이전 패널이 닫히는지 확인한다.
5. DB 연결 시 수정 버튼에서 올바른 PM/버전을 선택하고 관리 화면의 해당 기록이 열리는지만 확인한다. 저장은 사용자가 변경 검토 후 명시적으로 진행한다.

자동 검사는 `tests/test_ui_equipment_drawer.py`, `tests/test_equipment_drawer_gateway.py` 및 기존 히트맵/설비/관리 화면 회귀 테스트에서 수행한다.
