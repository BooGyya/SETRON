## 여는 곳

- 버전 히트맵 타일 클릭 · 키보드 선택. 라우트를 바꾸지 않고 캔버스 오른쪽에 560px 패널을 연다. 패널이 낮으면 패널 안에서만 스크롤한다.
- 버전 리플레이의 히트맵 타일(같은 패널, 그 시점 자료).

- 대시보드 설비 목록 패널의 행.

## 패널 내용 (읽기 전용)

맨 위 접기 버튼(툴팁 `접기 (Esc)`)과 제목 **설비 정보**. 그 아래 카드 순서:

| 카드 | 화면 글자 |
| --- | --- |
| 설비 정보 | 위험 상태 배지 · 목표 판정 배지(HPA는 배지 없음), `Site` · `Line`(없으면 `미지정`) · `모델` · `설비명` · `기준일` |
| SW 카드 | `현재 버전` · `목표 버전`. SW가 여럿이면 카드 제목에 모델(같은 모델이 여럿이면 PM 이름도). SW가 없으면 `SW 미등록 · 목표 비교 불가` |
| 위험 카드 | 위험 상태 배지 + 적용된 위험 기준 표(`위험 기준명` · `기준 버전` · `메모(설명)` · `적용 근거`). 표가 없으면 이유 문구(예: `현재 등록된 규칙에서는 위험 후보로 판정되지 않았습니다.`, HPA는 `HPA는 위험 분석에서 제외됩니다.`) |

- SW 카드는 같은 모델 · 계열 · 현재 버전 · 목표 버전인 PM끼리 한 장으로 묶는다(`observed_software`).
- 위험 표의 `적용 근거`: 버전 일치 · 버전 초과 · 버전 미만 · 필수 Item 미적용 · 버전 범위 내 결함 Item 포함. 미확인 근거는 표 아래 `미확인 · 판정 자료 확인 필요`로 따로 보인다. 근거가 연결되지 않은 위험 후보는 `적용된 위험 기준 정보를 확인할 수 없습니다.`
- 아이템 매니저에서 열면 정보 카드에 Item 적용 상태 배지와 `관측일` · `Item 기준일`, SW 카드에 `대응 릴리즈`를 보인다.

## 닫기

- 접기 버튼 · Esc · 패널 밖(어두운 배경) 클릭은 패널만 닫고 선택했던 타일로 초점을 돌린다. Tab 초점은 열린 패널 안에서 돈다.
- 새 조회 적용 · 조회 선택지 변경 · 다른 메뉴 이동 시 패널을 닫는다. 조건 초안만 바꿀 때는 열린 결과를 유지한다.

## 데이터 경계

- 설비 상세와 같은 전체 관측 · PM 비교 결과를 쓴다. Figma 예제 호기 · 버전 · 위험 사유를 실제 데이터처럼 쓰지 않는다.
- 목표 미달을 위험 후보로 추론하지 않고, 목표 달성이 위험 해제를 뜻하지 않는다. HPA는 분석 제외이지 안전 확정이 아니다.
- 패널에는 **수정 버튼이 없다.** 버전 값을 고치려면 데이터 관리 › 설비현황 › 현황표에서 고친다([데이터 관리](data-management.md)).

## 수동 확인 순서

1. 앱 실행 → 조회 → 버전 히트맵 → 타일 클릭. 뒤쪽 타일 · 왼쪽 메뉴가 그대로인지 확인.
2. 설비 정보 · SW 카드의 현재/목표 버전 · 위험 카드 확인.
3. 접기 버튼 · Esc · 배경 클릭으로 각각 닫고, 원래 타일 선택 · 스크롤이 유지되는지 확인.
4. 다른 설비를 연 뒤 새로 조회하면 패널이 닫히는지 확인.

자동 검사: `tests/test_ui_equipment_drawer.py`, `tests/test_equipment_drawer_gateway.py`, `tests/test_equipment_risk_table.py`, `tests/test_risk_candidate_reasons.py`.
